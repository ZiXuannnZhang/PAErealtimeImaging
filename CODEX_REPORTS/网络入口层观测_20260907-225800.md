## 实施结果

### Windows 接口、IP、UDP ingress sampler

NetworkDiagnostics::IngressSampler 位于低频运行快照路径，不在 recvfrom() 热路径调用 Windows API。每次采样：

1. 用 GetBestRoute2(AF_INET) 对每个 targetIP 做真实路由解析，导出 interfaceIndex 和 decimal-string 的 interfaceLuid；同时记录 targetMappings。调用传入 SOCKADDR_INET bestSource，loopback 路由测试已通过。
2. 用 GetAdaptersAddresses(AF_INET) 导出相关接口的 friendlyName、description、localIPv4、operationalStatus、MTU、receiveLinkSpeed、transmitLinkSpeed，四个目标共用接口时写入 sharedByTargets。
3. 用 GetIfEntry2(MIB_IF_ROW2) 导出 Windows interface counters：InOctets、InUcastPkts、InNUcastPkts、InDiscards、InErrors、InUnknownProtos、OutOctets、OutUcastPkts、OutNUcastPkts、OutDiscards、OutErrors。
4. 用 GetIpStatisticsEx(AF_INET) 导出 systemIpv4Counters：InReceives、InHdrErrors、InAddrErrors、InUnknownProtos、InDiscards、InDelivers。
5. 用 GetUdpStatisticsEx(AF_INET) 导出 systemUdpCounters：InDatagrams、NoPorts、InErrors、OutDatagrams。

所有 64-bit lifetime counter 均使用 decimal string。采样同时写入 wall-clock capturedAt 和进程内 monotonicMs。delta 的 identity 是接口 LUID + counter name 或 system scope + counter name；第一次采样为 deltaStatus=unavailable，当前值小于上次值为 deltaStatus=reset 且 delta=0，正常相邻样本为 deltaStatus=ok。IP/UDP 对象明确写入 scope=system_ipv4。

### MultiPortReceiver 入口观测

保持原有 socket 数量、端口、非阻塞、select()+drain-to-WSAEWOULDBLOCK、接收缓冲、线程优先级和 CPU affinity 不变，只增加 relaxed atomic 累计值：

- selectWakeups、selectTimeouts、selectErrors；
- recvHardErrors（排除 WSAEWOULDBLOCK）和 recvWouldBlockTerminations；
- maxDrainPackets、maxDrainDurationUs，并按 socket/card 记录 maxDrainPackets；
- maxReceiverLoopGapUs：同一 receiver 线程连续两次进入接收循环的 steady-clock 起点间隔最大值，包含本轮 select() 等待/线程调度时间。

只有包头已解析且原有条件允许计入 socketPacketsReceived 时才调用 raw tracker；没有改变 enqueue、处理或组包判断。

### 原始接收顺序和组包拒绝分类

CardStats::observeRawReceive(triggerSeq, packetSeq) 只做无锁整数比较和 relaxed atomic 累计：

- 同 trigger 内相对上一个接收值前进大于 1：sameTriggerForwardGapEvents 加 1，缺口数加到 sameTriggerForwardGapPackets；
- 同 trigger 内下降：sameTriggerBackstepEvents 加 1；
- 同 trigger 内相同：sameTriggerDuplicateSeqEvents 加 1；
- 新 trigger 后再次收到旧 trigger：crossTriggerLateArrivalEvents 加 1；
- 使用 int16/uint16 wrap-safe 差分，trigger 切换时不会把 packetSeq 重置当成同 trigger gap；
- 另保留 lastTriggerSeq、lastPacketSeq、rawSequenceInitialized。

PacketAssemblyBuffer::insertPacket() 改为返回 InsertResult，但原有 accepted、bitmap duplicate、offset out-of-range 的接受/拒绝路径完全不变；DataProcessor 只对既有结果分类累计：

- staleTriggerPacketsDiscarded：原 Step 1 已经执行 continue 的 stale packet；
- assemblyDuplicatePackets：bitmap 已存在；
- assemblyOffsetOutOfRangePackets：offset 超出 buffer。

没有修改 stale 条件、trigger reset heuristic、base packetSeq 设计、PROC_BATCH_SIZE 或丢包统计语义。

## 未验证项与已知限制

- T4/T10/T11 是 Windows loopback deterministic replay；当前没有在真实采集服务器接入 FPGA/交换机/NIC 的实机窗口，因此 interface/IP/UDP counter 的真实变化仍需下一轮现场导出验证。
- 任务要求的接口 counters 是 Windows interface/IP/UDP 层累计值；首次样本 delta 不可用，重启或 counter reset 会标为 reset。
- maxReceiverLoopGapUs 包含线程调度和 select() 等待，不能单独证明某一层发生丢包。
- 本任务有意保留跨-trigger reorder 和 PacketAssemblyBuffer 首包 base 序号风险，只记录 staleTriggerPacketsDiscarded、assemblyDuplicatePackets、assemblyOffsetOutOfRangePackets，不改变既有行为。
- 完整 Windows 构建使用本机已有且未提交的 CUDA import/runtime；测试 DLL 也只放在被忽略的 build 目录，未作为源码交付。

必须明确的层级限制：

> Windows interface InDiscards/InErrors、system IP/UDP counters 只能帮助定位到 Windows ingress 层级，不能自动证明具体是 FPGA、交换机、NIC hardware、USB transport、driver 还是 NDIS 的哪一层；如果下一轮实机仍无法区分，后续再单独评估 ETW/NDIS tracing、外部抓包或厂商 NIC statistics。
