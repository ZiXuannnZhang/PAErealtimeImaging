## 3. 设计目标：建立明确的 Start Fence

### 3.1 禁止再次简单交换顺序

不得用以下任一方案直接结束任务：

```text
A. Commit -> Start
B. Start -> Commit
```

原因：

- A 会接受 Start 前 trailing packet；
- B 会丢失 Start 后、Commit 前已经到达的新 session 首包。

必须引入一个明确的 **Start fence**，把“某张卡的本地 Start 命令已经成功发出”作为该卡进入新 session admission 的边界。

### 3.2 推荐的最小语义

具体实现可由 Codex选择，但最终行为必须等价于：

```text
all receivers/processors PREPARED
all receivers/processors ARMED
receiver admission 仍关闭

for each target card:
    send Start command to that card
    if local sendto succeeds:
        publish/commit that card's Start fence
        only then may that card's datagrams enter new session
    else:
        that card remains closed
        transaction later rolls back

4/4 card Start fences committed
-> session RUNNING
```

重点：

1. Start fence 必须是 **per-card** 或等价能表达逐卡 local-send 边界的机制；不得在第一张卡 send 前就全局打开所有 card admission。
2. 某卡的 packet 在该卡 Start `sendto` 成功之前必须继续作为 `sessionBoundaryPacketsDiscarded` 处理，不进入 `observeRawReceive()` / DataProcessor。
3. 某卡 Start `sendto` 成功以后到达的 packet 必须可以立即进入该卡新 session，不能等待四卡全部发送完才统一开门，否则会重新制造首包丢失窗口。
4. receiver 的 raw-order observation 与 processor enqueue 必须继续共享同一个 admission decision。
5. 4/4 全部成功后 controller 才进入 canonical `RUNNING` / `measurement_started`。
6. 3/4、2/4 等 partial start 仍按现有 rollback 语义处理；已临时开放的成功卡必须在 rollback/disarm 中重新关闭并清空本轮 processor state，不得留下 partial assembly 进入下一 session。
7. Start fence 必须与当前 `measurementSessionToken` 绑定，旧 fence/token 不得跨 session 复用。
8. 所有 fence reset 必须发生在现有 prepare/disarm/rollback 生命周期内。

### 3.3 关于不可区分的外部迟到包

本任务关闭的是**软件可定义的 Start 边界竞态**：

> receiver 已经观察/dispatch 到的 Start-fence 前 packet 不得在 fence 后获得新 session 身份；Start-fence 后的新 packet不得因全局 admission 尚未打开而丢失。

在不修改 FPGA wire protocol、没有硬件 session epoch/ACK 的前提下，若一个旧 UDP datagram 在物理网络/驱动层直到 Start fence 之后才首次到达 host receiver，则软件无法仅凭 payload 100% 判断它来自旧 session还是新 session。本任务不得为此引入 FPGA 协议修改，也不得伪造“数学上绝对可区分”的声明。

但是：现有 receiver prepare/arm socket quiescence barrier 必须保留，Start fence 应紧接 quiescence 后执行，使软件自身不再额外制造可避免的边界窗口。
