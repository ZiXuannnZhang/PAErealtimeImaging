# GPU 预处理与环形 FBP

2026-11-06。接续两通道性能优化候选 `86722a2`。标准 CUDA 12.8 + Qt 6.8/MinGW Debug 工具链不变。

改进 FBP 默认尝试 CUDA 融合路径。每个输入分批上传一次原始 float A-line；清理非有限值、反相、双精度亚采样校正、可选双精度时变低通、DBR 掩蔽、幅值限制、DelayCut、跨块中值及去均值均在 GPU 上进行。处理后的列直接传给现有 cuBLAS 矩阵乘法和反投影。非零校正保留 `nextpow2(N+64)`、正频 Nyquist 和滤波前的 float 舍入，零校正旁路 FFT。去均值仍从第 100 点起以 double 累加，采用 GPU 并行归约，浮点和的顺序可不同。

CPU 保留原始数据、物理通道和角度检查，以及按模板估计卡间延迟。每通道每波长仅留两条 GPU 历史数据；缺口按边界复制，重复角度报错，轮末冲刷后清空状态。无效块停止成像并重置两波长累积，不发布半幅图。原始数据保存和最终显示图回传保持原有路径。DAS 不使用此融合路径。

显存工作区在采集前准备，覆盖普通块和配置允许的模板前缀。超出融合工作区上限或准备失败时，自动模式继续使用原分段路径；运行失败沿用停止并复位语义。诊断工具可用 `--fbp-preprocess-backend staged` 和 `--fbp-preprocess-backend cuda` 在同一二进制中分别强制两种路径。日志 `fbp_preprocess` 表示实际所选路径，`backend` 仍表示时变低通后端；融合路径的 `accumulate_ms` 包含中值、去均值和 GPU 历史保存。

两通道功能验证：

- `ring_fbp_fusion_two_channel_test` 对照 CPU 预处理参考和独立整段 FBP，检查双方向、分层、拼接、低通、掩蔽/限幅、轨迹缺口、轮末、重复轨迹失败，以及多块模板前缀。
- `ring_timevar_cuda_test` 和 `ring_timevar_cuda_reference_test` 验证 GPU 低通数值及 MATLAB 参考。独立 FBP CUDA 核心仍使用原 MATLAB 图像和矩阵参考。
- `benchmark.py --fusion` 使用同一个服务二进制按两种顺序对比融合与分段路径。双波长合计 40 Hz、2 通道、7500 点、每块 10 触发，时变低通开启，合成校正 +0.375 样点。每轮保留 20 个稳态块和首块记录。合成顺序提交用于估算 250 ms 处理预算，实机须另行确认连续采集、显示和保存。

现场验收用完整测试包和现场标定；合成 +0.375 样点不会写入程序默认值。八通道性能测试暂缓。
