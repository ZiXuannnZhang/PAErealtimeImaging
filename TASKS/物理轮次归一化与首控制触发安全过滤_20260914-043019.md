# 1. Objective

建立统一的物理轮次归一化组件，例如：

```text
PhysicalRoundNormalizer
```

将底层观测到的 physical trigger 流，安全映射成生产路径使用的 logical scan trigger 流：

```text
Physical trigger stream
        ↓
完整 TriggerGroup
        ↓
PhysicalRoundNormalizer
        ↓
Logical scan trigger stream
        ├── FileSaver
        └── Ring realtime imaging
```

目标是解决已确认的硬件控制行为：配置期望一圈 4000 个有效扫描 trigger，但控制 FPGA/控制程序会额外产生 1 个 startup/control trigger，导致实际物理输出 4001 个 trigger。

正常情况下应实现：

```text
1 startup/control trigger + 4000 valid scan triggers
        ↓
physical observed = 4001
logical accepted = 4000
```

同时必须保证：如果 startup/control trigger 已经在 ingress 之前或 ingress 路径中丢失，软件不得再误删第一条真正扫描 A-line。

# 2. Problem / Evidence

当前“开始测量”被设计为一次性软件工作。一个 measurement session 内可以重复发生多个真实物理采集轮次；物理轮次主要通过：

1. 达到一圈预期逻辑触发数量；
2. 无触发 timeout reset；

判定，而不是要求操作员每圈重复 START。

当前实际硬件行为：

```text
有效扫描 trigger 期望 = 4000
额外 startup/control = 1
实际 physical trigger = 4001
```

如果 4001 全部进入生产语义，会造成：

```text
有效 A-line 4000 -> 4001
保存落盘 trigger 数 +1
RingBlockAssembler 计数 +1
双波长奇偶/角度计数可能错位
block progress 多推进 1
成像圈末/出帧计数与物理扫描不同步
下一圈 reset/boundary 可能漂移
```

当前 `RingBlockAssembler` 对完成 trigger 会推进 `m_globalTrigger`，timeout 才真正 `resetRoundState()`；不存在安全的物理轮次级 startup/control trigger 过滤。

当前 `DataProcessor` 在完整 `TriggerGroup` 形成后，通过 `deliverAssembled()` 将同一 group 分发到 save/display/ring。因此只在 `RingBlockAssembler` 中过滤无法修复保存路径；保存和实时成像必须共享同一分类结果。

同时，当前另一条已知问题是部分平台存在 startup/round-start ingress 丢包，甚至整 trigger 在 stage1 前消失。因此：

```text
first observed trigger != guaranteed physical startup/control trigger
```

严禁将“软件看到的第一个 trigger”直接作为过滤条件。

# 3. Core Invariants

## 3.1 禁止基于位置盲删

禁止以下规则：

```text
drop first observed trigger
drop first complete trigger
drop first trigger after timeout
drop first trigger after START
drop first N packets
drop trigger merely because count exceeded 4000
```

只有存在正向协议证据时才能分类为：

```text
StartupControlTrigger
```

证据不足时必须 fail-open：保留 trigger，并记录 ambiguity。

## 3.2 Physical accounting 与 logical accounting 分离

现有底层统计继续反映真实网络/物理事实，例如：

```text
socketPacketsReceived
processorPacketsDequeued
packetsReceived
packetsDropped
triggersComplete
triggersPartial
raw packet sequence diagnostics
```

如果物理上完整观察到 4001 个 trigger，底层统计应继续显示 4001。

新增 logical round accounting 至少能表达：

```text
logicalTriggersAccepted = 4000
startupControlTriggersFiltered = 1
```

不得通过篡改底层计数器把 4001 伪装成 4000。

## 3.3 保存与实时成像共享同一 classification

同一个 physical trigger 不允许出现：

```text
FileSaver: accepted
Ring imaging: filtered
```

或反之。

分类必须唯一，并由所有生产 consumer 复用。

## 3.4 多卡不能独立猜测

多个 `DataProcessor` 分别处理不同采集卡。禁止每卡独立维护：

```text
isFirstTrigger
logicalCount
roundGeneration
```

从而产生不同结果。

同一 physical trigger 身份必须获得相同：

```text
classification
roundGeneration
logicalTriggerIndex
```

共享 normalizer 必须 thread-safe、幂等，并确保 logical counter 对同一 physical trigger 只推进一次。

## 3.5 正常一圈只由 logical scan trigger 推进

对于：

```text
logicalTriggersPerRound = 4000
```

只有 `LogicalScanTrigger` 能推进 logical count。

`StartupControlTrigger`：

```text
不进入正常保存
不进入 RingBlockAssembler
不推进波长奇偶
不推进角度
不推进 block progress
不推进 logical frame/round count
```

## 3.6 timeout reset 保持有效

未完成 4000 logical trigger 时发生无触发 timeout：

```text
partial round
→ timeout boundary
→ next physical round
```

必须清理旧 round 的 pending/logical/Ring/reconstruction 状态。

但是 timeout 后的 first observed trigger 仍不得自动删除；仍需按协议证据分类。

# 4. Phase 0 — 强制协议证据调查

在修改生产过滤代码前必须完成。该阶段具有否决权。

必须从当前仓库源码、协议定义、已有模拟器/测试、诊断格式、硬件说明中回答：

## A. startup/control trigger 是否存在可识别身份？

检查是否存在：

```text
packet flag
trigger type
reserved field
command/state bit
特殊 packet/trigger header
固定 triggerSeq 关系
control-program generation
其它明确硬件标识
```

必须提供具体源码/协议证据。

不能以“通常它是第一个”作为身份依据。

## B. triggerSeq 的真实作用域是什么？

必须确认或明确标记 UNKNOWN：

```text
是否所有采集卡共享同一个 physical triggerSeq
是否各卡独立计数
是否每个物理轮次 reset
是否仅 FPGA reset 时 reset
是否跨控制程序启动连续
是否 modulo 65536 回绕
startup/control trigger 是否占用一个 triggerSeq
```

禁止仅从 C++ 注释反推 FPGA 物理协议。

## C. 4001 行为的发生范围

必须确认仓库证据是否能证明：

```text
每个 physical round 都是 1 + 4000
```

还是：

```text
仅控制程序首次运行/特定边界产生额外 1 trigger
```

如果仓库无法证明，必须写 `UNKNOWN`，不得擅自选一种。

## D. control trigger 完全丢失时是否可安全推断？

例如，只有在协议明确保证：

```text
上一轮最后 physical seq = N
control trigger = N+1
first scan = N+2
```

时，才能用观察到 `N+2` 推断 control trigger 已经在 ingress 丢失。

没有协议保证时不能实现该推断。

# 6. Recommended Design

若 Phase 0 获得足够协议证据，建立独立组件，例如：

```text
PhysicalRoundNormalizer.h
PhysicalRoundNormalizer.cpp
```

名称可以调整，但职责必须独立。

建议抽象：

```cpp
enum class PhysicalTriggerClass {
    LogicalScan,
    StartupControl,
    Uncertain
};

struct RoundDecision {
    PhysicalTriggerClass classification;
    uint64_t roundGeneration;
    uint32_t logicalTriggerIndex;
    bool roundStarted;
    bool roundCompleted;
    bool startupControlMissingInferred;
};
```

接口可按项目结构调整，但必须满足：

```text
thread-safe
同一 physical trigger decision 幂等
多卡重复查询得到同一 decision
logical count 对同一 physical trigger 只推进一次
支持 uint16 triggerSeq wrap
measurement session 切换完整 reset
timeout boundary 可显式 reset
```

决策缓存 key 必须能唯一定位物理 trigger，至少考虑：

```text
measurementSession
round context
physical trigger identity
```

不得只用裸 `uint16_t triggerSeq` 作为永久 key。

# 7. Recommended Integration Point

当前生产逻辑：

```text
Packet
 ↓
DataProcessor PacketAssemblyBuffer
 ↓
TriggerGroup
 ↓
deliverAssembled()
 ↓
save / display / ring
```

首控制 trigger 过滤不得放入：

```text
SocketReceiver
START fence
packet admission
PacketAssemblyBuffer packet insertion
```

优先放在：

```text

+
生产 consumer 分叉之前
```

逻辑上接近：

```text

        ↓
RoundNormalizer
        ↓

```

因为存在多个 `DataProcessor` 并发，Normalizer 必须是共享实例，或采用其它能够严格证明等价的共享分类模型。

如果实际结构表明 `NetworkController` 等位置更合适，可以调整，但执行报告必须证明所有 invariant 仍成立。

# 22. Engineering Principle

本任务目标不是：

```text
“想办法少算一个 trigger”
```

而是建立：

```text
physical trigger identity
        ↓
有证据的 classification
        ↓
logical acquisition semantics
```

必须同时安全处理：

```text
A. startup/control trigger 被主机收到
   → 有证据过滤

B. startup/control trigger 已在 ingress 丢失
   → 不得再误删第一条真实 scan
```

如果当前协议无法区分 A 与 B，则软件层没有足够信息安全完成过滤。

此时：

```text
PROTOCOL_BLOCKED
```

就是正确工程结果。
