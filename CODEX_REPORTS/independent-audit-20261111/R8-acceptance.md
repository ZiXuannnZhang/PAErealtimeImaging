# R8 验收：诊断导出与正式日志轮转

实施起点 `66ccff3edd52d40b6dbee99ef04027713ba8da13`。写入、快照和回归由 gpt-6.1-terra / high 分工实施，主代理复审并独立构建验证。

活动 writer 继续使用当前分段和一个 .previous，按原容量轮转。轮转不再申请根目录 .retention.lock；跨进程的轮转和主动文件读取由每个 run 自己的 .history.lock 协调。锁异常首次等待最多 2.5 s、随后立即尝试，丢弃、关键丢弃和有界 fallback 仍可观测；锁恢复后正常推进。活动文件使用无缓冲 Qt 写入，使成功写入的前缀可供捕获；processed 包含已结算的丢弃项，written 只由成功写入推进，flushed 在刷新成功后记录处理边界，flush 成功与日志完整性分别报告。轮转在任何移除或改名前预检路径，清理重验受保护目录和已知文件。

本地活动快照在写入侧互斥下同步固定序号及五类日志当前和 previous 前缀，单 run 原始前缀限 32 MiB、附加元数据限 8 MiB，进程共享快照原始字节限 80 MiB。快照只复制操作时已写入的字节，之后的解析与 ZIP 不持 writer 锁。请求持有快照时可重试，最后一份引用析构时释放内存额度。单 run 导出继续合并边界内的点击时队列和 fallback，按序号去重；时间窗的正式记录仅包括固定磁盘前缀，点击时尚有待写数据则明确标为截断，不能当作已正式写入。磁盘目录不可用仍可得到带缺失/错误标记的单 run 内存证据。

历史时间窗捕获固定目录列表，根锁保护历史文件直到读取完毕，进入 ZIP 和扩展前已释放，未执行的请求析构也释放。历史选择重试仍用原目录集合；路径已被清理时明确显示缺失。普通捕获遇到其他进程尚在写的活动 run，会明确列为不完整来源并继续其它来源；手工请求若提供明确活动序号和刷新回调，先刷新再取每 run 的轮转锁，仅从固定前缀读，跨文件一致性无法证实时明确标为截断。未修改独立 PAimage 二进制 trace 的存储和保留契约。

主代理复现：6144 字节分段，正常写入 4 条再挂起 ZIP 扩展，同时再写 8 条。基线 flush=1、queue_drop=8、rotated=0、zip=1；修复后同一探针 flush=1、queue_drop=0、rotated=1、zip=1，两个版本的边界均为 4，最终序号均为 12。正式回归用两份请求并发暂停 ZIP，暂停期间再写 24 条，检查多次轮转回执、正式文件中最新记录、丢弃 0、各 ZIP 边界和去重；后续导出读取新记录，失败无残留 ZIP，放弃请求释放 pin，历史与活动混合导出在扩展前释放根锁。原有测试还检查真实字节配额不足、历史清理、活动/崩溃日志、内存 fallback 和显式活动边界。独立容量探针用 28 MiB 历史前缀：并发允许两份，第三份明确拒绝，释放一份后重试成功，writer 仍为零丢弃。

定向命令：`ctest --test-dir <audit-tests> --output-on-failure -R "^(diagnostic_recorder_test|diagnostic_dialog_test|diagnostic_time_window_test|paimage_trace_bundle_test|startup_diagnostics_analyze_test)$"`。主代理独立定向验收 5/5 通过（9.72 s）。
