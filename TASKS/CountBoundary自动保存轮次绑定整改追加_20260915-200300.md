# 2. 当前需要处理的生产时序

## 2.1 CountBoundary observer 的调用顺序

当前 `PhysicalRoundNormalizer::classify()` 在一轮第 N 个 LogicalScan 被识别时，会完成类似如下状态转换：

```text
当前 logical round generation = G
最后一个 logical identity 被接受
→ classification 仍属于 G
→ roundComplete = true
→ normalizer 内部 generation 前进到 G+1
→ 发出 CountBoundary(event.roundGeneration = G+1)
→ observer 执行
→ classify() 返回最后一个旧轮 classification
```

当前 HostOutput 的顺序是：

```text
normalizer.classify(...)
→ observer 可能同步执行
→ tagNormalization(...)
→ capture/resolve save session generation
→ tagSaveSession(...)
```

因此有一个必须保留的事实：

> CountBoundary observer 可能先于“旧轮最后一个 TriggerGroup 的 save session generation 打标”执行。

多卡情况下，同一最终 physical trigger identity 的其它卡还可能更晚到达，并由 normalizer cache 返回同一个旧 `roundGeneration = G`。

所以本任务不能采用“CountBoundary 一发生就只修改一个全局 current save generation，然后所有 TriggerGroup 都读取这个全局值”的方案。

## 2.2 当前目录切换时机

当前 CountBoundary 的下一 auto-save generation 主要等到旧轮最后 reconstruction frame / `frameEnd` 时才推进。

这会产生如下窗口：

```text
CountBoundary(G+1) 已经发生
→ 旧轮 final reconstruction snapshot 尚未返回
→ 下一物理轮 control 到达并被过滤
→ 下一轮第一个 LogicalScan 已属于 G+1
→ 保存路径仍可能读取旧 auto-save generation S
```

于是可能形成：

```text
new LogicalScan.roundGeneration = G+1
new LogicalScan.sessionGen       = S
```

而在旧轮 final frame 返回后，auto-save generation 才推进到 `S+1`。

本任务需要消除这个时序依赖，同时保留旧轮 final reconstruction/PNG 的目录归属。

# 3. 设计目标：数据路由与最终帧展示目录解耦

需要明确拆分两个概念：

```text
A. data routing generation
   决定 LogicalScan / TriggerGroup 写哪个 auto-save directory

B. presentation / reconstruction directory
   决定旧轮最后 reconstruction frame / PNG 写哪个目录，
   以及 UI 当前显示/记录的目录
```

CountBoundary 时允许二者在不同时间更新。

期望时序：

```text
旧轮 G 最后 logical identity 被分类
        ↓
CountBoundary(target round = G+1)
        ↓
准备并注册下一数据目录 S+1
建立 round binding：G+1 → S+1
        ↓
旧轮最终 TriggerGroup / 同一 identity 迟到卡：round G → S
下一轮 LogicalScan：                    round G+1 → S+1
        ↓
旧轮 final reconstruction snapshot 稍后返回
        ↓
旧轮 PNG 仍写 S
        ↓
完成旧轮 final-frame 处理后，UI/presentation target 切到已经准备好的 S+1
```

# 4. 保存 generation 必须按 physical round identity 解析

## 4.1 Round binding

扩展现有 auto-save coordinator 或增加等价结构，建立：

```text
(measurementSession, roundGeneration)
    → sessionGen
    → directory
```

名称不限，例如：

```text
RoundBinding
SaveRoundBinding
sessionGenerationForRound(...)
```

但必须满足：

```text
同一个 measurementSession + roundGeneration
始终解析到同一个 sessionGen。
```

同一个 physical logical identity 的所有卡，只要 normalizer 给出的 `roundGeneration` 相同，就必须得到相同的 `sessionGen`。

CountBoundary 为下一轮准备新 generation 时：

```text
OLD classification.roundGeneration = G
仍解析到 S

NEW classification.roundGeneration = G+1
解析到 S+1
```

不能仅依据“当前全局最新 generation”决定。

## 4.2 HostOutput save stamp

当前 normalized save path 需要从：

```text
captureSaveSessionGen()  // 无 round identity
```

调整为等价的 round-aware 解析：

```text
resolveSaveSessionGen(
    classification.measurementSession,
    classification.roundGeneration)
```

实际 API 名称由执行代理决定。

关键要求：

```text
save session generation
由当前 TriggerGroup 自己的 physical round identity 决定。
```

如果 auto-save 未开启，保持现有 manual-save / generation=0 语义。

如果 auto-save 已开启，但 normalized LogicalScan 无法解析到 round binding：

```text
不得静默 fallback 到 current generation
不得静默 fallback 到 previous directory
不得静默写到 base directory
```

必须采用明确的 fail-closed 行为并记录诊断。

# 5. 初始 round binding 生命周期

必须保证：

```text
第一个 measurement session 的 roundGeneration=0
在第一个 LogicalScan save stamp 之前已经有合法 binding。
```

允许的实现方式包括：

```text
measurement session begin 时显式绑定
```

或：

```text
首个 ControlFiltered 事件到达时，
把当前已准备的 auto-save generation 绑定到 round 0
```

或其它能够证明发生在第一个 LogicalScan 前的方式。

不要依赖“第一次 LogicalScan lookup miss 时用 current generation 懒绑定”，因为当 `configuredLogicalTriggersPerRound = 1` 时，CountBoundary observer 可能已经先执行。

生命周期至少覆盖：

```text
measurement restart
source restart/resume
auto-save disable/reconfigure
manual ↔ auto-save transition（若产品允许）
```

旧 measurement 的 round binding 不得污染新 measurement。

---

# 6. CountBoundary：同步准备下一数据 generation

收到：

```text
CountBoundary(event.roundGeneration = G+1)
```

且 auto-save enabled 时，在 observer 返回前完成：

```text
reserve next sessionGen S+1
→ create/prepare directory
→ register S+1 → directory
→ bind (measurementSession, G+1) → S+1
→ publish binding
```

publish 之前必须保证目录映射已经可供保存线程解析。

如果目录创建/注册失败：

```text
不得把 NEW round 数据写到 OLD directory
```

应采用明确失败路径并记录错误。

---

# 7. 旧轮 final reconstruction / PNG 目录保留

CountBoundary 同步准备 `S+1` 后，不能立即把旧轮 final reconstruction/PNG 的目标目录覆盖掉。

需要保存一个待完成的 presentation transition，至少包含：

```text
measurementSession
oldRoundGeneration
nextRoundGeneration
oldSessionGen / oldDirectory
newSessionGen / newDirectory
boundary identity
```

旧轮 final reconstruction frame 返回时：

```text
1. old PNG 使用 oldDirectory
2. 执行现有 final-frame-driven UI/frame reset
3. 将 UI/presentation target 应用为已经准备好的 newDirectory
4. 不再次 allocate/increment generation
```

也就是说：

```text
CountBoundary = generation allocation / round binding
final-frame callback = presentation apply only
```

如果 final-frame callback 迟到，而系统已经进入更新的 presentation generation，则迟到 callback 不得把 UI/reconstruction directory 倒退。

需要按至少：

```text
measurementSession
roundGeneration
sessionGen monotonicity
```

做 stale apply 防护或提供等价机制。

# 8. TimeoutBoundary 保持现有 round-aware 语义

如果实现统一成 round-binding resolver，TimeoutBoundary 可复用同一机制。

必须保持以下行为不变：

```text
partial round timeout
→ 下一 round binding 在 next LogicalScan 前可解析
→ next control filtered
→ next LogicalScan 写下一目录
→ old queued group 保持旧目录
→ timeout UI/frame/block reset 正常
→ stale OLD reconstruction snapshot 按 submit_index identity 处理
```

本任务不要求重新设计 stale snapshot、ZMQ identity 或 timeout detection。

# 9. Required Tests

以下测试必须加入自动化测试，不能只在报告中描述。

## C1 — CountBoundary race：下一轮数据先于旧轮 final snapshot

构造：

```text
auto-save enabled
round G 正常达到 count boundary

故意不投递 / 不处理 old final reconstruction snapshot

立即送：
next control
next round first LogicalScan
```

检查：

```text
old final LogicalScan.roundGeneration = G
old final LogicalScan.sessionGen       = S

new LogicalScan.roundGeneration        = G+1
new LogicalScan.sessionGen             = S+1
```

并检查实际文件：

```text
old round data files → directory S
new round data files → directory S+1
```

随后再投递 old final reconstruction snapshot，检查：

```text
old final PNG → directory S
presentation/UI target → S+1
generation 不重复推进
```

## C2 — 最终 identity 多卡迟到

至少 2 张卡，最好使用当前生产卡数 fixture。

构造：

```text
最终 logical trigger identity T
card A 先到并触发 CountBoundary(G+1)
card B/C/... 同一个 T 稍后到
```

检查同一最终 identity 的所有卡：

```text
roundGeneration = G
sessionGen       = S
```

同时下一轮首个 LogicalScan：

```text
roundGeneration = G+1
sessionGen       = S+1
```

## C3 — N=1 顺序测试

配置：

```text
configuredLogicalTriggersPerRound = 1
```

输入：

```text
control
one logical scan
```

该 LogicalScan 会立即触发 CountBoundary。

检查该唯一 LogicalScan 仍写当前轮 generation；下一轮 LogicalScan 写下一 generation。

## C4 — 三个连续 count-complete rounds

同一 measurement session：

```text
(control + N logical) × 3
```

检查：

```text
每个 round 的数据只进入该 round 对应目录
同一 round 所有卡 generation 一致
old final PNG 使用该 round 的目录
next-round data 不依赖 old final UI callback 才开始写新目录
每个 CountBoundary 只分配一次下一 generation
```

## C5 — Saver backlog + delayed final reconstruction

制造保存线程 backlog：

```text
OLD groups 已 stamp OLD sessionGen 并排队
CountBoundary 准备 NEW round binding
old final reconstruction callback 延迟
NEW groups 已 stamp NEW sessionGen 并排队
```

排空后读取实际 `.dat` 内容和目录，检查 old/new group 未混写。

## C6 — final-frame apply 不重复分配 generation

CountBoundary 已经准备 next generation 后，old final frame 返回时检查：

```text
只保存 old PNG + apply presentation target
不创建额外 generation
不产生空目录
不跳号
```

## C7 — delayed presentation apply

构造迟到 presentation callback，检查它不能覆盖一个更新的 presentation target。

如果生产状态机从结构上不可能出现该序列，需要用 deterministic test 或 invariant assertion 证明该事实。

## C8 — Timeout regression

继续覆盖：

```text
partial round
→ timeout
→ UI callback 延迟
→ next LogicalScan 立即到达
```

检查 next round 仍解析到新的 auto-save generation/directory。

## C9 — Manual save / auto-save off

关闭 auto-save 后检查：

```text
manual save 路径仍正常
round binding 不影响 manual-save 数据
```

## C10 — Lifecycle

覆盖至少：

```text
measurement restart
auto-save off/on
source restart/resume
```

检查旧 measurement 的 round binding 不泄漏到新 measurement。

# 15. 明确禁止的实现方式

禁止：

```text
CountBoundary 后只改一个全局 currentGeneration，所有 TriggerGroup 都读取它

sleep / wait / processEvents() 等待 old final frame 先返回

依赖 UI callback 及时执行来保证 next-round save generation

old final PNG 与 new data 强制共用一个立即切换的目录变量

final-frame callback 再次 allocate / ++ generation

round binding lookup 失败时 fallback 到 current generation

只测试计数，不检查实际目录和 .dat 内容

只测试单卡，不测试 CountBoundary 后同一最终 identity 的迟到多卡
```
