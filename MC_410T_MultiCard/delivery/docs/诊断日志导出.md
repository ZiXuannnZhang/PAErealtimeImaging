# 诊断日志导出

本功能用于保存 PAimage 生产采集链的可追溯运行证据。当前程序是
`PAimageReceiverDiagnostics.exe`；项目整体状态以根目录 `PROJECT_STATUS.md` 为准。

## 使用方式

在主窗口“运行日志”区域选择“导出诊断日志…”，选择当前或历史运行，填写可选现场说明并选择 ZIP 保存位置。

故障发生后应尽量及时导出。停止监听后仍可导出；重启程序后也可以选择已持久化的历史运行。
导出本身不重新扫描网络、不发送 CONFIG/START/STOP。

## 导出内容

典型 ZIP 包含：

| 文件 | 用途 |
| --- | --- |
| `summary.txt` | 人类可读摘要和完整性提示 |
| `runtime.log` | UI / Qt / startup 日志 |
| `events.jsonl` | 带时间、session/correlation 的结构化事件 |
| `network.json` | 记录时本机网络快照 |
| `settings.json` | 当次参数/诊断状态 |
| `manifest.json` | 导出边界、格式、校验与完整性 |

实际字段以当前 executable 生成的 manifest/schema 为准。

## 证据边界

- target/card 编号是本地目标列表位置，不自动证明设备类型；
- ARP/可达性、18 字节 ready、60 字节 CONFIG ACK 是不同证据；
- `sendto` 成功只证明本机发送调用成功；
- 应用 trace 无法替代 wire/NIC/driver 层抓包；
- 日志缺失、轮转、写盘失败或异常退出会降低证据完整性。

基本判读：

```text
wire/pktmon 有包，但 stage 1 无包
  -> NIC / driver / socket / receiver 继续定位

stage 1 有包，stage 2 admission/source 丢弃
  -> 应用 session / START / SourceCore 边界

SourceCore 完成，但 save/sync/imaging 缺失
  -> 对应下游 queue / FileSaver / ImagingBypass / Ring 路径

wire 侧也无包
  -> 继续向 FPGA / 控制系统 / 网络侧取证
```

## 当前状态说明

诊断系统是观测工具，不改变采集协议和 round policy。

A/B/C/D 当前实机验证范围已通过，但底层额外 startup trigger 的精确 FPGA/LabVIEW 来源仍未证明；
因此历史报告中的“待真机验证”“卡五”“4001”等阶段性描述不能直接作为当前项目状态。
