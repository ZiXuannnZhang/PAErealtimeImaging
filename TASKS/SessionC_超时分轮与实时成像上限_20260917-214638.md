# Session C — 超时分轮、可变长度生产链与实时成像上限

## 1. Objective

Session A/B 已完成并通过独立软件审查。Session C 负责把已经存在的 physical-round policy 真正接入**可变长度生产轮次**：

1. 当 `disableCountBoundary=true` 时，configured logical count 不再是 physical round 边界，而仅作为 realtime imaging cap；
2. physical idle timeout 必须在**没有下一枚 trigger 到来时主动关闭当前轮次**；
3. TimeoutBoundary 必须完成数据目录切轮、旧轮图像捕获、Ring 残留丢弃、Imaging/CUDA reset、新轮 clean start；
4. raw data 在 imaging cap 之后仍继续保存，直到 timeout boundary；
5. early timeout / variable-length round 不得伪装成“重建完整”。

本阶段不再修改 Session A/B 的 UI、默认值、missing-trigger 统计口径。

# Part I — Current architecture facts to preserve

## 5. HostOutput raw/save path and sync/imaging path are already separated

当前：

```text
HostOutput::card(Frame)
  -> PhysicalRoundNormalizer::classify
  -> startup filter check
  -> resolve AutoSave round binding
  -> tag saveSession
  -> workers_.pushCard
  -> DataProcessor::deliverAssembled(group, save=true, displayAndRing=false)
```

因此 card path 是 raw/save authority。

当前 sync path：

```text
HostOutput::sync(...)
  -> shared normalizer classification
  -> startup filter check
  -> workers_.pushSync
  -> consumeSync
  -> DataProcessor::deliverAssembled(group, save=false, displayAndRing=true)
  -> publisher/display/Ring/CUDA
```

因此 configured-count imaging cap 的首选最小落点是 **HostOutput::sync()**：在 shared normalization 之后、`workers_.pushSync(...)` 之前做 gate。

不要通过停止 card/save path 来实现 imaging cap。

当前已经存在：

- `PhysicalRoundNormalizer::timeoutBoundary(...)`；
- classify-next-trigger 时的 idle timeout fallback；
- `NetworkController` 20 ms `m_paimageTimer -> pollPaimage()`；

- timeout PNG / old-directory 相关代码。

Session C 应**复用并收口这些 seam**，不要建立第二套 round/save/reset architecture。

## 7. Confirmed current gaps

### 7.1 No-trigger idle gap is not currently a Normalizer boundary

Normalizer 的自动 idle 检查目前主要发生在下一枚 new distinct trigger 进入 `classify()` 时。

现有 `MainWindow::m_ringTimeoutTimer` 每 250 ms 只做独立 PNG 保存，而且：

```text
requires imaging enabled
requires recon save enabled
requires recon save directory
requires round.state == CollectingScan
```

它**不调用 Normalizer TimeoutBoundary**，因此：

- 没有下一 trigger 时，round generation / save binding / Ring reset 不会及时完成；
- partial-startup round（例如 X=7 只收到 3 枚）处于 `AwaitingControl`，还会被该 timer 排除。

### 7.2 Screenshot-before-reset is not guaranteed

当前 TimeoutBoundary observer 把 PNG 保存排入 UI queue 后，source callback 继续立即清 `ImagingBypass` / reset Ring/CUDA。

因此“旧轮图像捕获发生在 reset 前”目前没有严格顺序保证。

Session C 必须冻结并证明**capture-before-reset**；磁盘写完成可以晚于 reset，不要求同步 drain FileSaver。

### 7.3 No configured-count imaging cap

`disableCountBoundary=true` 后 logical index 已能超过 configured count，但 `HostOutput::sync()` 仍全部进入 display/Ring/CUDA。

Session C 需要添加 cap。

# Part II — Realtime imaging cap

## 8. Frozen cap semantics

设：

```text
N = configuredLogicalTriggersPerRound (>0)
```

只有在：

```text
disableCountBoundary == true
```

时启用 realtime imaging cap。

### Logical indices

```text
0 .. N-1:
  raw save      YES
  sync/display  YES
  Ring/CUDA     YES

N .. infinity:
  raw save      YES
  sync/display  NO
  Ring/CUDA     NO
```

例如 N=4000：

```text
logicalTriggerIndex 0..3999 进入实时成像
logicalTriggerIndex >=4000   只保留 raw/save
```

不要把 `N` 当 modulo 周期；不要在同一 physical round 重新从 0 开始成像。

---

## 9. Cap must use Session A classification

必须依据：

`PhysicalRoundClassification.logicalTriggerIndex`

而不是：

- triggerSeq 数值；
- per-card counters；
- UI `已采集`；
- Ring assembler 的内部 global counter。

多卡同一 physical trigger 已由 Normalizer shared classification 保证只占一个 logical index。

推荐逻辑等价于：

```text
classify sync frames
if startup-filtered:
    return

if disableCountBoundary &&
   decision == LogicalScan &&
   logicalTriggerIndex >= configuredLogicalTriggersPerRound:
    return before workers_.pushSync(...)

workers_.pushSync(...)
```

可以增加明确的诊断计数/trace reason，但不得因此改动业务语义。

---

## 10. Count-enabled compatibility

当：

```text
disableCountBoundary == false
```

Session A 既有 CountBoundary 行为必须完全保持：

- index `N-1` 是 final logical trigger；
- `roundComplete=true` one-shot；
- `isFinalLogicalTrigger=true` stable；
- generation++；
- next round startup filter restart。

不要叠加新的 imaging-cap branch 改写 count-enabled 路径。

---

## 11. Timeout reopens cap

`disableCountBoundary=true` 时，timeout boundary 后 Normalizer 新 generation 的第一枚 logical trigger 必须重新从：

`logicalTriggerIndex = 0`

开始，imaging cap 自动重新开放。

优先直接依赖 classification index，不维护额外 mutable `imagingFrozen` 状态。

# Part III — Canonical active idle-timeout owner

## 12. One external timeout owner

production physical idle timeout 必须由一个外部定时 owner 主动轮询 Normalizer。

推荐复用已经存在的：

```text
NetworkController::m_paimageTimer
interval = 20 ms
-> NetworkController::pollPaimage()
```

不要让 MainWindow 250ms timer、RingBlockAssembler standalone timer、NetworkController timer 三者分别制造 production boundary。

`RingBlockAssembler::setTimeoutManagedExternally(true)` 保持。

---

## 13. Add an atomic/deterministic Normalizer idle poll seam

不要使用：

```text
snapshot -> UI 判断已超时 -> 无条件 timeoutBoundary()
```

这种 TOCTOU 方式，因为在 snapshot 与 boundary call 之间可能到达新 trigger。

新增一个在 Normalizer mutex 内完成“判断 + boundary”的 production seam，命名可自行选择，例如：

```cpp
bool timeoutBoundaryIfIdle(std::int64_t observedMonotonicNs);
```

或等价 API。

它必须在同一锁域内检查：

```text
currentPhysicalDistinctCount > 0
timeoutResetNs > 0
hasLastDistinctTrigger
now >= lastDistinctTriggerTimeNs
now - lastDistinctTriggerTimeNs >= timeoutResetNs
```

满足时：

- latch lastCompleted physical/filtered counters；
- clear current counters/state；
- roundGeneration++；
- timeoutBoundaryResets++；
- restart startup filter；
- emit exactly one TimeoutBoundary event；
- no next-visible trigger in event。

不满足返回 false/no-op。

保留现有强制测试 seam `timeoutBoundary(...)` 的显式语义；不要用本任务破坏 Session A tests。

---

## 14. HostOutput / Backend / NetworkController propagation

生产定时链建议：

```text
NetworkController::pollPaimage()
  -> Backend / HostOutput timeout poll
  -> PhysicalRoundNormalizer timeoutBoundaryIfIdle(now)
```

使用与 SourceCore / Normalizer 相同的 `SocketReceiver::now()` steady-clock domain。

该 polling 必须独立于：

- imaging 是否 enabled；
- recon PNG saving 是否 enabled；
- auto-save 是否 enabled；
- Normalizer 当前 state 是 `AwaitingControl` 还是 `CollectingScan`。

只要当前 physical round 已观察到至少一枚 new distinct trigger，就可以被 idle timeout close。

这包含 Session A 已冻结的 partial-startup case：

```text
startupFilterTriggerCount = 7
只收到 3 个 distinct startup triggers
idle timeout 到期
=> physical round 必须关闭
=> lastCompletedPhysicalDistinctCount = 3
=> lastCompletedStartupFilteredCount = 3
```

---

## 15. Race / exactly-once requirements

### Poll wins

如果 timer poll 先关闭 round：

- generation++ exactly once；
- 下一 trigger 进入新 generation；
- startup filter restart。

### Next trigger wins

如果下一枚 trigger 在 timer poll 前到达并触发 classify 内既有 idle fallback：

- classify 可以完成 timeout boundary；
- 后续 timer poll 看到新 round current empty/new anchor，不得再重复 timeout。

### Cached late card

旧 trigger 的 late/cached card：

- 不刷新 idle anchor；
- 不产生第二个 TimeoutBoundary；
- 保持旧 classification/RoundIdentity；
- 不进入新轮 raw directory/Ring identity。

---

## 16. Retire the independent MainWindow timeout-save owner

现有 `m_ringTimeoutTimer` 不得继续独立根据 wall/UI snapshot 决定“到点保存 PNG”。

Session C 后：

- TimeoutBoundary event 是 timeout screenshot / save rollover / Ring reset 的唯一 production authority；
- 可以删除该 timer 的 timeout-save action，或保留 timer 做无副作用 UI/diagnostic polling；
- 不得再让它直接设置 `m_ringTimeoutSaveDone` 或独立调用 `saveWindowPngs()`。

# Part IV — TimeoutBoundary production closure

## 17. Boundary identity and AutoSave binding

Normalizer TimeoutBoundary event 中的：

`event.roundGeneration`

是 boundary 后的**新 generation**。

继续使用现有：

```cpp
commitAutoSaveBoundary(
    event.measurementSession,
    event.roundGeneration,
    AutoSaveBoundaryKind::Timeout,
    ...)
```

要求同步完成 directory prepare/register/publish 后再允许新 round raw frame resolve。

保持现有 fail-closed contract：

- 新 round binding lookup 失败不能回落到旧 directory；
- FileSaver 已经入队的旧 round TriggerGroup 保留旧 `sessionGen`；
- 不同步 drain 旧 FileSaver queue；
- 不等待磁盘 flush 才开始新 round。

---

## 18. Old-round screenshot ordering

TimeoutBoundary 必须保存**旧轮最后可用实时重建画面**。

顺序冻结为：

```text
1. boundary identity / AutoSave new binding commit
2. capture old-round reconstruction presentation
3. reset/discard old Ring + Imaging/CUDA state
4. allow clean new-round presentation
```

其中第 2 步要求的是 **capture-before-reset**。

磁盘写本身可以异步完成；不要为了顺序保证而同步 drain raw FileSaver。

如果现有 `saveWindowPngs()` 直接包含磁盘 I/O，执行代理可以提取一个最小的“UI-thread capture payload / queued write” helper，或采用其他等价方法；但必须提供 deterministic event-order 证据。

### Directory

截图必须使用 boundary commit 返回的：

```text
oldDirectory/recon_png
```

不能因为 UI target 已切到新目录而把旧图保存到新 round folder。

manual/non-auto-save 模式继续沿用现有 `m_reconSaveDir` 行为。

---

## 19. Ring residual behavior

TimeoutBoundary 是 physical round boundary，不是 reconstruction completion。

必须复用：

`RingBlockAssembler::resetAfterPhysicalTimeout()`

语义：

- 清 `m_pending`；
- 清 partial block / phase；
- 不提交 synthetic partial Ring block；
- 旧 residual 计入既有 diagnostics；
- 要求下一数据使用更新的 RoundIdentity；
- late old identity fail closed / stale drop；
- next new identity clean start。

不要把旧 residual 与新轮数据拼成完整 block。

---

## 20. Imaging/CUDA reset

继续使用既有：

```text
ImagingBypass::clear(StaleSession)
RingBlockAssembler::resetAfterPhysicalTimeout()
ImagingController::sendRingReset()
producer submit-index stale cutoff
```

要求：

- reset exactly once per `(measurementSession, roundGeneration)` boundary；
- `ring_reset` 提交失败时保持现有 fail-closed snapshot admission；
- 不强制 CUDA 把 early/partial round 标记 complete；
- 不等待不存在的 final block；
- 不制造额外 final snapshot。

# Part V — Early timeout is NOT reconstruction-complete

## 21. Frozen non-completion semantics

可变长度 round 可能在：

```text
800 / 2371 / 3980 / >4000
```

任意 logical count 处因用户停止扫描并出现 2–10 秒 idle gap。

TimeoutBoundary 只表示 physical round 被分隔，不表示 configured reconstruction 已完整。

因此禁止：

- 强制 `reconstructionComplete=true`；
- 合成 `sourceRoundComplete=true`；
- 修改/缩短 `expectedBlocks`；
- 伪造 final trigger；
- 生成 partial Ring block 补齐尾部；
- 等待 CUDA “final completion”；
- 通过 angle modulo 让超长数据重新覆盖前面的角度；
- 修改 CUDA geometry 来容纳 >N realtime data。

configured logical count 在 disable mode 中只是 realtime imaging/reference length，不是 raw-save hard limit。
