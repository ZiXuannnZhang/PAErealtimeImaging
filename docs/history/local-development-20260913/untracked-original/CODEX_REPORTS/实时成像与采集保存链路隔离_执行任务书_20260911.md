SocketReceiver → SourceCore → immutable complete Frame

分支一：Frame → 独立 SaveQueue → SaveWorker → FileSaver

分支二：Frame → 非阻塞 ImagingQueue.try_push → ImagingWorker → RingBlockAssembler → ImagingController / ImagingSvc

必须使用两个独立的有界队列、同步对象和统计对象。接收线程向 ImagingQueue 提交时只能使用非阻塞 try_push；队列满立即丢弃成像旁路数据，不能等待或反压 SaveQueue。成像 worker 不得调用接收、组包、保存控制或 UI 接口，也不能持有接收锁、组包锁或保存队列锁。

## 实现要求

### 保存主路径

- 保存 worker 保留原有文件格式、文件关闭和触发计数语义。
- 保存 worker 不调用 ringFeedSink、ImagingController 或 UI。
- 成像队列满、服务异常或成像线程退出时，保存继续运行。
- 保存队列满仍按现有策略处理，但必须记录明确结果。

### 成像旁路

成像入队接口必须返回明确结果，至少区分：Accepted、Disabled、QueueFull、Stopping、InvalidFrame、StaleSession、ServiceNotReady。

要求：

- 队列容量固定；
- 入队不等待；
- 优先传递共享只读 Frame 或移动所有权，避免重新复制完整原始数据；
- 不得使用 void 回调表示成像提交成功；
- 不得把回调返回等同于实际入队成功；
- 成像旁路失败不得重试阻塞保存路径。

### 成像过滤和复制

成像旁路尽早过滤多余首触发、无效 session、不完整帧和未启用通道，再执行块组装或复制。禁止继续先复制全部卡 A/B、再在 RingBlockAssembler 内过滤的路径。

### 结果语义

重构 DataProcessor::deliverAssembled 或等价接口，使 saveAccepted、displayAccepted、imagingAccepted、imagingDropReason、publisherAccepted 和 exception 独立表达。只有实际进入成像队列时 imagingAccepted 才能为 true，不得继续用无条件 ring=true 表示成功。

### 生命周期

开始采集：建立 measurement session，清理旧成像队列，启动保存 worker，再启动接收。成像服务可稍后启动，未就绪不影响采集。

停止采集：停止接收，等待保存队列排空并关闭文件，再停止成像旁路接收，记录并丢弃剩余成像数据，最后停止成像 worker 或通知服务退出。

成像服务异常、重启、共享内存不可用时，只记录错误并丢弃成像旁路数据，不停止接收、不停止保存、不改变有效触发计数。

## 禁止事项

- 不得在接收线程调用 ImagingController；
- 不得在保存 worker 等待成像队列；
- 不得使用无界队列或 sleep 等待服务；
- 不得把成像队列满转化为接收等待；
- 不得使用全局 mutex 同时保护保存和成像队列；
- 不得修改首触发过滤规则；
- 不得把最后不足一个成像块误报为 UDP 丢包；
- 不得把成像旁路丢弃统计为采集入口丢包。
