# 接收诊断快速候选操作卡

2026-09-10：按用户最新指令，收敛为单次不超过两分钟的快速实测候选。不是原任务书全部能力的验收版本，不宣称修复丢包。

## 实测步骤

1. 启动独立目录中的 PAimageReceiverDiagnostics.exe。标题应为“PAimage接收诊断版”。配置写入同目录 PAimageReceiverDiagnostics.ini，首次只读复制原程序注册表参数。核对四卡、25 微秒、250 MHz、同步块 50、成像和保存条件。
2. 使用新的保存目录。默认启用原始入口和轻量时序。每次监听运行总时长控制在两分钟内（包含等待）；下一实验重新停止/开始监听，生成新 run。
3. 外部触发前后分别点击“实验标记”，输入 trialA / 1-start 和 trialA / 1-end。外部仍每轮 1+4000 次触发。标记是人工时间，不是物理边沿。
4. 停止保存、停止采集、停止监听，再导出覆盖本轮的诊断 ZIP。保留新数据目录和包内 paimage-traces 目录。
5. 反馈 ZIP、是否保存、额外触发报文号及确认依据；未知时明确留空，不根据首到包猜测。

先做原程序和本候选各一轮分时对照，再按结果决定下一轮。不同时运行两个程序。原程序只提供自身现有日志。

## 离线分析

Python 3.11 或更新版本：

    python diagnostic-tools/paimage_trace_analyze.py capture.zip --run-id RUN_ID --packets 35 --samples 6250 --rounds-json rounds.json --output analysis.json

rounds.json 使用 rounds 数组，每项填写 trialId、roundId、extraTrigger、effectiveCount=4000、basis=user-confirmed。仅在用户确认额外触发报文号后填写。跨 session 重用同号时增加 session 或 startNs/endNs；否则结果保留 unknown。有效触发分类不改变原始保存输出。

## 能力和限制

本候选记录入口缺槽、整触发不可见、已确认轮次有效计数，以及 select、recvfrom、入口统计、core 锁等待、组包、输出入队和 worker 长耗时。

系统抓取启动未启用。receiver_system_capture.ps1 check 仅检查工具；WPR profile 通过本机语法解析，未验证目标线程实际事件。不能据本候选区分网卡、驱动、内核丢弃与抢占，四卡同症状不等于同因。

时序在阶段结束后记录，异常退出的未闭合区间可能不可见；尚无阶段开始快照。QPC/UTC 与 steady_clock 误差未验证。推荐停止监听后导出；活动导出的时序可能不完整。系统 ETL 自动绑定、完整延迟注入验证和逐轮保存汇总留待后续。GUI/真实硬件由用户验收。

入口磁盘上限 1 GiB，时序 256 MiB，内存队列各 16 MiB。达到限额明确报告不完整。每次监听不超过两分钟；超过该时长不属于本候选验证范围。
