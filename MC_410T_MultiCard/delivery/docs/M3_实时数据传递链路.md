# M3 实时数据传递链路（UDP → 内存 → 组包 → 重建）

> 2026-08-07 修订：根据 ogprog 原版源码与实际硬件信息重新确定链路。
> 原“1 触发=1 A-line”的理解修正为：**1 触发 = 8 通道同步采集 = 8 根 A-line**。

> 目标：采集卡每触发 1 根 A-line，经 UDP 入内存；每 200 根 A-line 组包，
> 送环形重建流程实时显示。本文档确定链路方案，待信息确认后实现适配器。

## 1. 实际链路（依据 ogprog 源码 + 硬件信息）

```
LabVIEW（设定重频，控制激光器 532/1064 按触发交替出光）
   │ 触发（同时给卡组 8 通道）
   ▼
采集卡组（4 卡 × 2 通道 = 8 通道同步采集）
   │ 1 触发 = 8 根 A-line（每通道 1 根，各通道同为当前触发波长）
   │ 每卡 UDP 包（packetSeq + triggerSeq + 1440B 载荷）
   ▼
MultiPortReceiver（WinSock 多路接收线程，每卡独立端口）
   ▼
DataProcessor（按触发重组：card c 的 A/B 两通道数组）
   │ 原始 int16/32 差分相位 → float；再转频率（线性模式用）
   │ 环形模式下保留原始/频率数据用于组包
   ▼
RingBlockAssembler（新组件）
   │ 按勾选通道累计 T 个触发 = 组包 N = 选中通道数 × T 根 A-line
   │ 每根 A-line 附带：通道号、扇区角度、波长（触发奇偶）
   ▼
ImagingController::submitRingBlock(raw + metadata)
   ▼
MC_410T_RingShm（共享内存）
   ▼
ImagingSvc（环形模式）
   按波长切分 → 每通道/每 A-line 角度映射 → 预处理 → ring_recon_cuda
   ▼
wl1 / wl2 帧 → ringImageReady → 环形控制台双图刷新
```

## 2. 已确定/已具备

- 触发粒度：1 触发 = 1 根 A-line；双波长由 LabVIEW 外部交替，采集卡不做切分。
- 组包粒度：每 N 根 A-line 一组（面板“组包列数”，默认 200）。
- 切分/对齐位置：ImagingSvc 预处理内完成（已实现并自检通过）。
- 精度：面板支持 single/int16（int16 量化因子可调），适配器负责 UDP 载荷 → float 转换。
- 重建/显示：环形控制台已具备参数面板、模拟采集、双波长实时显示。

## 3. 待确认信息（影响适配器实现）

依据硬件事实，以下问题需要确认后才能实现 RingBlockAssembler 与扇区角度映射：

1. **A-line 数据内容与通道映射**：UDP 每触发的 A/B 双通道中，
   一根 A-line 用 A、B、还是 A+B？载荷是原始幅度、差分相位还是频率？
2. **每根 A-line 采样点数**：与 MATLAB `SampDepth=4000` 的关系；
   实际卡配置的采样点数/采样率是多少？
3. **int16 物理含义与换算**：是否仍为 Q0.15 差分相位（当前 DataProcessor
   默认 `Δφ/32768 → kHz`）？环形重建需要的是原始时间序列还是换算后的频率？
4. **组包边界**：接收端按 triggerSeq 连续计数每 N 个触发组包即可？
   triggerSeq 是否连续/每块是否重置？丢帧时组包如何处理（丢弃不完整块或补零）？
5. **单卡还是多卡**：环形采集使用一张卡的一个通道，还是多卡/多通道拼接？
6. **实际时序**：A-line 重频（Hz）与每块间隔；双波长起始点（第 1 根 A-line 是 532 还是 1064）。

## 4. 确认后实现范围

- `RingBlockAssembler`：按卡累计 N 根 A-line → 组包（float32，不切分）。
- `DataProcessor` 环形模式：按上述映射导出 A-line → assembler；
  组包完成通过队列/信号交给 GUI 线程调用 `submitRingBlock`。
- `MainWindow`：环形模式下启动/停止组包通路，面板“数据精度/量化因子/组包列数”生效。
- 丢帧策略：默认丢弃不完整块（与线性扫描一致），后续可按需补零。
