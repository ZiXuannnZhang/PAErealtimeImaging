## 实现范围

- 新增 `--startup-policy=bypass|legacy`；诊断构建默认 `bypass`，`legacy` 恢复 1000 ms。请求值和实际生效值都写入运行身份与生命周期记录。
- `bypass` 仅取消原启动缓存/空闲确认路径，不新增清 socket、跳过第一包/触发、等待稳定或启动延迟。
- 接收线程用 80 字节固定记录和预分配有界队列记录完整循环、select、drain、成功/失败 recvfrom、poll、端口、缓冲区、线程启动和控制阶段。成功 recvfrom 与原始入口记录共用 ingress ID，drain ID 独立。
- 循环流从监听线程启动持续保留到 256 MiB 预算；2 秒空闲后的首采样包产生 BurstMark，分析器直接计算其前后各 5 秒窗口覆盖。后台写盘，接收线程不做 JSON、文件 I/O 或系统命令；队列丢弃、预算耗尽、写失败和导出截断均显式标记。
- 补齐 START/STOP、每卡反馈接收与 UI 派发、组包清理、成像请求/服务就绪/停止/初始化/清队列、保存请求与实际应用时间。
- 新增独立 Pktmon/WPR 脚本：限定采集卡 IPv4、UDP 与 8000—8004 端口，128 字节截断，Pktmon 256 MiB 内存模式，WPR GeneralProfile；拒绝碰触既有会话/过滤器，失败不生成伪成功结果。
- 同一监听的多轮系统抓取通过带有效期的 `active-trial.json` 使用独立 `trialId`。文件只由脚本和应用 UI 线程处理，不进入接收线程。
- 离线分析器按地址、端口、包号、触发号、时间窗口及明确轮次关联；对 Pktmon 多组件重复观测去重，允许 16 位触发号跨轮重用，按证据边界输出应用丢弃、系统层至应用入口缺失、延迟、未知或不可判定。
- 前端文案改为“报文不完整触发”和“不完整触发缺包数”，不把现有累计字段解释为物理触发缺失。
