# 开发与验证

## 版本与任务协作

`main` 是正式源码基线。开发任务从最新 main 或已明确的方向基线创建独立分支，记录目标、基线 SHA、不变量、范围和验收条件。合并或继续开发前先用 `git merge-base --is-ancestor` 和 `git rev-list --left-right --count` 核对祖先关系，不对分叉分支执行强制推送。

当前开发方向和准确版本见 [项目现状](项目现状.md)。诊断证据、本地构建产物和被 `.gitignore` 排除的数据不提交。提交前还需检查待上传对象，单个文件不得达到或超过 GitHub 的 100 MiB 上限。

## 本机构建

本机使用 Qt 6.8.0、MinGW 13.1 和 CMake。工具链路径可按实际安装位置调整。以下示例从仓库根目录生成 Debug 构建：

```powershell
$env:PATH = ('D:/Qt/Qt6.8.0/6.8.0/mingw_64/bin;D:/Qt/Qt6.8.0/Tools/mingw1310_64/bin;').Replace('/',[char]92) + $env:PATH
$cmake = 'D:/Qt/Qt6.8.0/Tools/CMake_64/bin/cmake.exe'
& $cmake -S MC_410T_MultiCard/delivery -B MC_410T_MultiCard/delivery/build/mingw_make -G 'MinGW Makefiles' -DCMAKE_BUILD_TYPE=Debug -DCMAKE_CXX_COMPILER=D:/Qt/Qt6.8.0/Tools/mingw1310_64/bin/g++.exe -DCMAKE_MAKE_PROGRAM=D:/Qt/Qt6.8.0/Tools/mingw1310_64/bin/mingw32-make.exe -DCMAKE_PREFIX_PATH=D:/Qt/Qt6.8.0/6.8.0/mingw_64 -DUSE_ZEROMQ=ON
& $cmake --build MC_410T_MultiCard/delivery/build/mingw_make -j 8
```

不要复用其他 checkout 或旧工具链生成的 CMake 缓存。修改 CUDA ABI 后，应同步重建 DLL、导入库和所有调用端。

## 测试

独立测试工程位于 `MC_410T_MultiCard/delivery/tests`：

```powershell
& $cmake -S MC_410T_MultiCard/delivery/tests -B MC_410T_MultiCard/delivery/build/tests_mingw_debug -G 'MinGW Makefiles' -DCMAKE_BUILD_TYPE=Debug -DCMAKE_CXX_COMPILER=D:/Qt/Qt6.8.0/Tools/mingw1310_64/bin/g++.exe -DCMAKE_MAKE_PROGRAM=D:/Qt/Qt6.8.0/Tools/mingw1310_64/bin/mingw32-make.exe -DCMAKE_PREFIX_PATH=D:/Qt/Qt6.8.0/6.8.0/mingw_64
& $cmake --build MC_410T_MultiCard/delivery/build/tests_mingw_debug -j 8
& 'D:/Qt/Qt6.8.0/Tools/CMake_64/bin/ctest.exe' --test-dir MC_410T_MultiCard/delivery/build/tests_mingw_debug --output-on-failure
```

Qt 测试启动失败时，先检查运行时 DLL 和平台插件路径。网络回环测试使用本地端口，端口冲突时应先确认占用进程。历史测试记录只证明对应 SHA 和环境，不代表当前分支已重新通过。

## 提交前检查

```powershell
git status --short
git diff --check
git diff --cached
git rev-list --objects --cached
```

明确添加文件路径后，再核对暂存区中没有构建目录、诊断证据或大文件。推送到任务分支后，用 `git ls-remote` 核对远端 SHA。
