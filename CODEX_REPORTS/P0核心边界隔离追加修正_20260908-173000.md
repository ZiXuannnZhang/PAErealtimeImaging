## 3. 实际设计修正

### 3.1 Receiver-aware admission

MultiPortReceiver 新增 receiver-thread-owned command queue：

    Prepare -> Arm -> Commit -> Disarm

Prepare 先关闭 admission，再在 receiver 线程中排空每个 socket 到 WSAEWOULDBLOCK；排空在 bounded timeout 内无法完成时返回失败。Arm 再次 quiesce，但保持 admission 关闭。所有 receiver 和 DataProcessor barrier 成功后先提交 receiver Commit，再立即发送硬件 Start；因此首个生产 datagram 不需要等待硬件 Start 之后的 receiver 命令，旧 trailing packet 仍会被边界状态拒绝，不会因为 ingress token 已更新而获得新 token。

生产 run() 和测试注入共用 dispatchDatagram()：

1. 合法 datagram 先计入 socketPacketsReceived；
2. 非 RUNNING 或无 active token 时计入 sessionBoundaryPacketsDiscarded，直接结束；
3. 只有 RUNNING 才调用 observeRawReceive()；
4. 只有 RUNNING 才通过 enqueuePacketForSession(packet, receiverToken) 入队。

因此 PREPARING/ARMED/trailing packet 不会建立新 raw anchor、不会进入新 assembly，也不会增加 staleTriggerPacketsDiscarded、packetsDropped 或 triggersPartial。正常 select -> drain recvfrom -> WSAEWOULDBLOCK 路径未改变。

### 3.2 Teardown 结果传播

MeasurementSessionTransaction::teardown 对全部 receiver 和 processor 执行 bounded disarm，聚合：

    hardwareStopSucceeded
    receiverSuccessCount / receiverFailCount
    processorSuccessCount / processorFailCount
    reason

正常 Stop 顺序为 hardware Stop -> receiver/processor disarm/reset。只有硬件 Stop 本地发送成功且全部 teardown barrier 成功，才记录 measurement_stopped 并进入 DISARMED。任一失败都记录 measurement_stop_failed，保留 session ID，进入 Fault；后续 Start 被拒绝，Stop 可使用同一 session ID 重试。Start partial rollback 同样检查 Stop rollback 和所有 disarm 结果，不能无条件把本地状态当作 clean。

### 3.3 Pending session ownership

sendStartMeasure 在生成 ID 后的 config-failed 路径立即清理；queued Start/Stop 在配置失败、监听 start rollback、监听 stop 和命令队列清理路径由 clearPendingMeasurementRequests() 统一清理。executeStartTransaction 在 prepare、arm、hardware send、partial rollback 失败后不留下 orphan pending ID；teardown 不完整时保留真实 session ID 并设置 Fault，而不是用 clear() 掩盖不确定状态。失败恢复成功后才允许新的 Start 生成新 ID。

### 3.4 Boundary diagnostics / canonical 去重

Start、armed、start command、started、stop command、stopped/stop failed、rollback 的 canonical marker 由 NetworkController 统一记录；MeasurementSessionTransaction observer 只记录必要的单次步骤，忽略与 controller 已写入的 canonical marker，避免同名重复。

start prepare、started、stop command、stopped、stop failed、start rollback 都主动记录 settings snapshot；stop/rollback 后再记录 card cumulative runtime counter 和 runtime ingress/interface snapshot。字段包含 session ID、config ID、command success/fail、receiver/processor barrier counts、outcome/reason。
