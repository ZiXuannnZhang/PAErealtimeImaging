# 实时成像与采集保存链路隔离：日志字段

## 入口与 SourceCore

PAimage 二进制 trace 保留 `receive`、SourceCore 决策、完整/不完整卡帧、启动过滤、重复包、偏移越界、同步过期和停止截断。`TraceRecord` 的 `session`、`correlation`、`card`、`trigger`、`packet`、`threadId` 用来关联入口包和输出对象。

`paimage.snapshot/source_snapshot` 记录 `recvfromDatagrams`、`sourceCompleteCards`、`sourceStartupFilteredCards`、`sourceStartupFilteredSync`、`sourceStartupIncompleteCounter`、`sourceRuntimeIncompleteCounter`、接收缓冲和接收线程优先级。

## 保存队列

`paimage.snapshot/source_snapshot` 新增：

- `saveQueueEnqueued`：保存队列成功入队数。
- `saveQueueDequeued`：保存 worker 出队数。
- `saveQueueCurrentDepth`：当前深度。
- `saveQueuePeakDepth`：峰值深度。
- `saveQueueFull`：按原有每卡 400 帧上限拒绝的新帧数。
- `saveWorkerMaxNs`：保存 worker 单帧回调最大耗时。

逐对象 trace 的 stage 5 保留 `CardQueued`、`CardFull`、`CardConsumed`、`CallbackFailed`、`SavingDiscard` 等结果；stage 7 reason 0 记录 `DataProcessor::DeliveryResult::save`，可区分排队、队列满、消费成功和消费失败。

## 成像旁路

`imaging.bypass/imaging_queue_snapshot` 每个 UI 统计周期记录：

- 入队：`enqueueAttempts`、`enqueued`、`dequeued`、`currentDepth`、`peakDepth`。
- 丢弃：`dropDisabled`、`dropQueueFull`、`dropQueueBusy`、`dropStopping`、`dropInvalidFrame`、`dropStaleSession`、`dropServiceNotReady`、`dropCallbackFailed`、`dropOnClear`。
- worker：`processed`、`processFailed`、`maxSubmitNs`、`maxWorkerNs`。
- 成像块：`blocksFormed`、`blocksSubmitted`、`blocksSkipped`、`blockExceptions`。
- 会话：`session`。

PAimage stage 7 reason 2 的 value 是 `ImagingSubmitResult` 数值，只有 value 0（`Accepted`）代表实际进入成像队列。此记录带 SourceCore 的 session、触发号、卡号、入口 correlation 和调用线程 ID。

## 结果判读

- 入口未收到：`recvfromDatagrams` 或逐包 trace 本身缺失。
- SourceCore 未组出完整帧：检查 SourceCore `TriggerSwitch`、`Timeout`、`SyncExpired` 与 incomplete counter。
- 保存丢弃：检查 `saveQueueFull`、stage 5 `CardFull` 或 stage 7 save 失败。
- 保存成功：stage 7 save 为 `Consumed`，并结合 FileSaver saved count/文件大小。
- 成像队列丢弃：检查 `dropQueueFull`、`dropQueueBusy` 等独立字段。
- 服务未就绪：`dropServiceNotReady`。
- 成像处理失败：`processFailed` 或 `blockExceptions`。
- 成像提交成功：`blocksSubmitted`。

最后不足一个成像块只体现为组包器当前进度，不计入 UDP 丢包。
