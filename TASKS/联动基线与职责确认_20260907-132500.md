### 3. ChatGPT 的主要职责

ChatGPT 负责：

- 理解项目整体架构和当前状态；
- 设计技术方案与任务规格；
- 明确 baseline、目标、边界、关键不变量、禁止修改范围和验收条件；
- 对高风险改动给出风险控制和回归要求；
- Codex 推送后重新读取 GitHub 远端 HEAD / diff / 必要源码；
- 检查实际执行的构建、测试和回归证据，而不是只接受“测试通过”的结论；
- 给出 `APPROVE` 或 `REQUEST_CHANGES` 审核结论。

除非用户明确改变分工，ChatGPT 不作为日常具体代码实现端。

### 4. Codex Desktop 的主要职责

Codex Desktop 负责：

- 从 GitHub 读取任务文档和最新 `main`；
- 从最新 `main` 创建独立任务实现分支；
- 按任务规格进行具体源码修改；
- 在本地环境完成适用的构建、测试和回归；
- 检查 staged diff，确保只包含任务范围内的修改；
- commit 并 push 实现分支；
- 提供精确的 commit SHA、修改文件、执行命令、测试结果和已知限制；
- 根据 ChatGPT 的 `REQUEST_CHANGES` 在同一任务分支继续修正并再次 push。

默认禁止：

- 直接 push `main`；
- force push；
- 自动 reset / 覆盖分叉历史；
- 擅自扩大任务范围；
- 修改任务明确列为禁止修改的 ABI、协议或算法行为。

### 5. 标准联动闭环

后续正式任务使用以下流程：

1. ChatGPT 在 `codex/task-docs` 发布带时间戳的任务文档，并写明代码 baseline SHA。
2. Codex fetch 远端并读取任务文档。
3. Codex 切换 `main`，使用 `git merge --ff-only origin/main` 同步；若失败则停止，不自动 reset 或 force。
4. Codex 从最新 `main` 创建独立实现分支。
5. Codex 实现、构建、测试、检查 diff、commit、push。
6. Codex 报告远端分支名、commit SHA、修改文件、命令、测试结果和限制。
7. ChatGPT 从 GitHub 重新读取实际远端状态进行独立审核。
8. ChatGPT 返回 `APPROVE` 或 `REQUEST_CHANGES`。
9. 默认由用户决定最终 merge；除非用户明确授权，否则不自动合并到 `main`。
