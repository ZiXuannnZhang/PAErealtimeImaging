# 2. 当前源码根因

## 2.1 UI frame count 与 physical timeout 未统一

当前 `m_imagingFrameCount` 在 Ring 重建帧返回时递增。

正常 count-complete 路径主要依赖最终 Ring frame 的 `seq % blocksPerFrame == 0` 清零，因此实机 count boundary 表现正常。

但是 `PhysicalRoundEvent::TimeoutBoundary` 的当前处理路径只清：

```text
ImagingBypass queue
RingBlockAssembler partial state
ImagingSvc ring reconstruction state
```

没有把：

```text
m_imagingFrameCount
m_ringBlockCounter
相关 per-round UI status
```

统一切换到新 round。

因此 timeout 后图像已经 reset，但 UI 仍显示上一轮累计帧数。

## 2.2 FileSaver 不认识 physical round generation

当前 `TriggerGroup` 已携带：

```text
roundGeneration
logicalTriggerIndex
physicalDecision
roundComplete
```

但 `FileSaver` 目前的文件边界主要来自：

```text
A. triggersPerFile 达到阈值
B. auto-save sessionGen 改变
```

它没有把 `roundGeneration` 当作保存文件边界。

因此当完整一圈恰好达到 `triggersPerFile` 时，看起来能正确分文件；但 partial round timeout 时：

```text
currentFileTriggers = M < triggersPerFile
```

下一 round 的 logical scan 会继续追加到同一个文件。

## 2.3 不能仅用 UI `requestCloseSavers()` 作为修复

保存是异步队列。boundary 发生时，上一轮 TriggerGroup 可能仍在 saver queue 中。

仅在 MainWindow/observer 收到 boundary 后直接 close 文件，会引入：

```text
旧 round 队列尚未消费
→ 文件先关闭/切换
→ 旧数据可能写入新文件
```

或者仅 close 不推进 file sequence，导致下一轮重新使用原文件名。

因此保存边界应优先由**每个 TriggerGroup 自带的 roundGeneration 数据面元数据**确定，而不是依赖 UI 控制面事件时序。

# 5. 保存路径 — roundGeneration 成为 authoritative file boundary

## 5.1 核心原则

`TriggerGroup::roundGeneration` 已存在，必须进入 FileSaver 的 round rollover 判定。

FileSaver 应维护类似：

```text
haveCurrentPhysicalRound
currentPhysicalRoundGeneration
```

当消费一个正常 `LogicalScan` TriggerGroup 时：

```text
if first logical group:
    adopt group.roundGeneration

else if group.roundGeneration != currentPhysicalRoundGeneration:
    flush previous buffers
    close previous physical-round file
    perform round rollover
    adopt new generation

then write current group
```

**判断必须发生在写当前 TriggerGroup 之前。**

这样即使上一轮数据在 saver queue 中排队，队列 FIFO 顺序仍保证：

```text
old generation groups
→ 完整写完 old file
→ first new generation group
→ FileSaver 自己 rollover
→ 写 new file
```

不要依赖 observer 与 saver queue 的跨线程先后关系。

## 5.2 手动保存模式（sessionGen == 0）

要求：

```text
同一用户保存目录
不同 physical round 不得共享同一个 .dat 文件
```

当 roundGeneration 改变时：

```text
flush
close current file
advance fileSequence safely
reset currentFileTriggers
next logical group opens new file
```

注意：

- 不得覆盖上一轮文件；
- `QFile::WriteOnly` reopen 同一名字不能作为轮次切分方案；
- 一个 physical round 可以因为 `triggersPerFile < logicalTriggersPerRound` 而产生多个文件；
- 但**一个文件绝不能跨 physical-round generation**；
- 若 `triggersPerFile > logicalTriggersPerRound`，round boundary 仍必须强制切文件。

因此：

```text
triggersPerFile = 文件容量上限
roundGeneration = 更强的文件边界
```

两者取先发生者。

## 5.3 自动保存模式（sessionGen > 0）

现有 auto-save generation / directory routing 可以保留。

要求：

- CountBoundary 与 TimeoutBoundary 均只能使 auto-save generation 推进一次；
- old queued group 必须继续按旧 `sessionGen + roundGeneration` 写旧目录；
- 新 round first logical group 必须进入新目录；
- 不得因为 UI timer 和 PhysicalRoundEvent observer 同时看到 timeout 而 double-advance；
- 不得发生空目录/跳号目录，除非现有产品语义明确允许并在报告中证明。

推荐：

```text
sessionGen 决定目录
roundGeneration 决定物理轮次文件边界
```

二者不要互相冒充。

## 5.4 FileSaver reset lifecycle

以下生命周期必须清理/初始化 physical-round file state：

```text
startSaving
stopSaving
measurement session restart
source restart / resume
manual ↔ auto save mode transition
```

不能让旧 measurement 的 `currentPhysicalRoundGeneration` 污染新 measurement。

# 6. UI / Ring 状态 — timeout 后必须切换为新轮次

## 6.1 TimeoutBoundary 必须重置 per-round UI counters

收到真正的 `PhysicalRoundEvent::TimeoutBoundary` 后，在 UI 线程完成：

```text
m_imagingFrameCount = 0
m_ringBlockCounter = 0
```

并重新刷新 Ring imaging status。

如果还有其它明确属于“当前物理轮次”的 UI counter，也应统一审查并重置；不要清累计诊断 counter。

目标实机表现：

```text
上一 partial round：输出 X 帧
→ timeout
→ 新 round 开始
→ 前端从 输出 0 帧 / 新轮进度重新计数
```

不得继续显示 X+1、X+2。

## 6.2 保留已工作的 CountBoundary 行为

当前 count-complete 的 `m_imagingFrameCount` reset 已通过实机验证，不得为了“代码统一”破坏最终帧到达时序。

特别注意：`CountBoundary` 在最后一个 logical trigger 被分类时产生，而最后的 reconstruction frame 可能尚未返回。

因此不要简单在 CountBoundary observer 当场：

```text
m_imagingFrameCount = 0
```

从而让上一轮迟到的最终 reconstruction frame 被计入下一轮。

允许采用：

```text
shared round-boundary coordinator
+ CountBoundary: 保留 final-frame-driven reset
+ TimeoutBoundary: immediate reset（因为上一轮已长期 idle，并主动清 stale queue/ring）
```

关键是两条路径最终都落到同一 `roundGeneration` 业务语义，而不是要求两种事件在同一个时刻执行完全相同代码。

## 6.3 timeout 后 stale reconstruction frame

检查 timeout reset 后是否可能仍收到上一轮已提交给 ImagingSvc 的迟到 frame。

如果当前已有 generation/session guard，复用它。

如果没有，至少保证：

```text
timeout reset 之后的旧 reconstruction frame
不得把新一轮 m_imagingFrameCount 从 0 错误增加
不得重新污染已清空图像
```

如需增加最小 generation token/epoch，仅限 Ring frame UI admission，不改数值重建算法。

# 7. 建议统一 Boundary Coordinator

为减少 MainWindow 中 Count/Timeout 分散逻辑，建议抽取一个窄职责 helper，例如：

```text
applyPhysicalRoundBoundary(event)
```

或等价结构。

它不重新判断是否发生 boundary，只消费 normalizer 事件。

职责可以包括：

```text
record boundary generation/reason
schedule/execute Ring reset
reset timeout per-round UI counters
coordinate auto-save generation exactly once
emit diagnostic action
```

保存文件真正的 data-plane rollover 仍以 `TriggerGroup::roundGeneration` 为权威，不应只靠该 UI helper。

# 8. CountBoundary 与 TimeoutBoundary 的最终业务语义

## CountBoundary

```text
最后一个 logical scan（index N-1）属于 old generation
→ normalizer CountBoundary
→ old round 的最后重建 frame 正常输出
→ UI frame count 在既有正确位置归零
→ 下一 visible trigger = control（过滤）
→ next logical scan carries new roundGeneration
→ FileSaver 在写它之前 rollover
```

## TimeoutBoundary

```text
partial logical scan M < N
→ idle > timeoutResetSec
→ next visible trigger 到达
→ normalizer 先产生 TimeoutBoundary、generation++
→ UI/Ring reset old partial round
→ 当前 trigger = control（过滤）
→ next logical scan carries new roundGeneration
→ FileSaver 在写它之前 rollover
```

两条路径必须保证：

```text
one physical round generation
↔ one coherent UI/Ring/save round identity
```

# 9. Required Tests

## T1 — 手动保存 partial timeout rollover（核心实机复现）

配置小 N，例如 N=5，`triggersPerFile >= N`：

```text
round0 control
round0 scan A,B,C
idle > timeout
round1 control
round1 scan D,E,F,G,H
```

断言：

- A/B/C 位于旧文件；
- D/E/F/G/H 位于新文件；
- 两文件无交叉 identity；
- control 均不保存；
- 新文件 sequence 不覆盖旧文件；
- old partial file 在 3 条时封口，不补到 5 条。

测试应验证文件实际内容，不只验证 `savedCount`。

## T2 — 手动保存完整 count boundary 回归

```text
control + N scan
control + N scan
```

断言两轮数据不共用文件，且保持当前实机已验证行为。

## T3 — triggersPerFile 与 physical round 不同

至少测试：

```text
triggersPerFile < N
triggersPerFile > N
```

要求：

- 单轮允许多个容量文件；
- 任何文件不得跨 roundGeneration；
- timeout partial round 仍强制封口。

## T4 — saver backlog / boundary race

人为阻塞或延迟 FileSaver 消费：

```text
old round groups 已入队但尚未消费
→ boundary 已发生
→ new round groups 入队
→ release saver
```

断言：

- old generation 全部写 old file；
- new generation 全部写 new file；
- UI observer 的执行先后不影响文件归属。

该测试用于证明不是依赖 `requestCloseSavers()` 的控制面时序。

## T5 — 自动保存 timeout generation

自动保存启用：

```text
partial old round
→ timeout
→ new round
```

断言：

- auto session generation 只推进一次；
- old queued groups 写旧目录；
- new logical groups 写新目录；
- 无 double-advance；
- 无跨目录混写。

## T6 — TimeoutBoundary UI counter reset

建立可测试 seam（不要依赖人工看界面），验证：

```text
m_imagingFrameCount > 0
m_ringBlockCounter > 0
→ TimeoutBoundary
→ 两者归零
→ status refresh 反映新轮状态
```

不得清除累计网络/诊断统计。

## T7 — CountBoundary UI 回归

验证现有 final-frame-driven frame count reset 不被新 coordinator 破坏。

重点覆盖：

```text
CountBoundary event 已发出
但 old round final reconstruction frame 稍后到达
```

最终必须在正确时机归零，而不是把 old final frame 计入 next round。

## T8 — timeout stale reconstruction frame

若生产链存在迟到 ImagingSvc frame 的可能，构造：

```text
old round frame pending
→ timeout reset
→ stale old frame 回来
→ new round starts
```

断言 stale frame 不推进新 round UI frame count，不重新污染新 round image state。

如果现有 protocol/seam 无法构造，报告必须明确证明为什么 reset/queue/session 机制已排除该可能，不能静默跳过。

## T9 — CountBoundary + subsequent idle 幂等

完整 round count-complete 后继续 idle > timeout：

- 不额外 rollover 空文件；
- 不 double-advance auto-save generation；
- 不 double reset UI/Ring。

## T10 — saving lifecycle reset

覆盖：

```text
stopSaving → startSaving
measurement restart
manual → auto（如产品允许）
auto → manual（如产品允许）
```

确保 FileSaver 不继承旧 physical round generation/file state。
