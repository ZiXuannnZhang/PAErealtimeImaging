## 4. Review finding A — diagnostic metadata mismatch

Session A 核心状态机已通过本轮代码审查，但 production diagnostics 仍残留旧的 fixed-first-visible 表述。

当前 `NetworkControllerPaimage.cpp` 的 round observer 中仍存在类似：

```text
firstVisibleFilterMode = true
acceptedControlInvisibleRisk = "first-visible-scan-may-be-filtered"
```

这与新策略并非始终一致：

- `startupFilterTriggerCount == 0` 时，不过滤任何 startup trigger，`firstVisibleFilterMode=true` 是错误观测；
- `startupFilterTriggerCount > 1` 时，策略是 configurable prefix filtering，单纯的 first-visible 描述不足以表达真实配置。

同时 Session A 已经在事件中提供：

```text
startupFilterTriggerCount
disableCountBoundary
```

Normalizer Snapshot 也已经按：

```text
startupFilterTriggerCount > 0
```

派生 `firstVisibleFilterMode`。

### Required correction

对 production diagnostic metadata 做最小一致性修正。

至少满足：

```text
firstVisibleFilterMode = (event.startupFilterTriggerCount > 0)
```

并修正 `acceptedControlInvisibleRisk`，使其不再在 `X=0` 时声称 first-visible scan 可能被过滤。

推荐保留既有字段名以减少 schema 扩散，可采用等价的动态值，例如：

```text
X == 0:
acceptedControlInvisibleRisk = "none"

X > 0:
acceptedControlInvisibleRisk = "startup-filter-may-consume-visible-scan"
```

具体字符串可以遵循现有诊断命名风格，但必须满足：

- X=0 的 metadata 不宣称存在 startup filtering；
- X>0 明确反映 configurable startup/prefix filtering，而不是把策略描述成协议已证明的控制字段；
- `startupFilterTriggerCount` 继续作为机器可读的权威数量字段；
- 不改变 Normalizer classification 行为。

如存在 run-config / periodic snapshot 中同类固定旧语义字段，一并检查并仅修正与本问题直接相关的矛盾；不要扩大 schema 重构。
