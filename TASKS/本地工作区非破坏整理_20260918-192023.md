
# 本地工作区非破坏整理 — 2026-09-18

## 1. Objective

远端 GitHub 已完成 canonical integration。本任务以最新 origin/main 为唯一事实基准整理本地工作区。

本任务采用用户指定的“零直接文件删除”策略：

~~~text
任何拟清理的文件/目录/旧构建/旧 worktree 内容
=> 不直接删除
=> 统一移入待删除目录
=> 生成清单与来源
=> 用户检查后自行删除
~~~

本地最终只保留：

~~~text
1. canonical main 工作树
2. 最新代码实现分支：
   codex/session-c-timeout-variable-round-20260917-214638
   d9daa2d7af6bb8341349e405433824e89e42bcd4
3. canonical main 最新构建：
   origin/main@36bb556441dedd760ab363f3df4f38872bbfc93f
~~~

解释：Session D 是 integration/validation + receipt/handoff 文档阶段，没有新的 production/test code commit，因此“最新实现分支”按最后一个包含 production/test 实现变化的 Session C 分支解释。Session D、A/B、physical-round、START 等远端分支继续保留在 GitHub 作为 traceability；本地不需要保留独立活跃 worktree/build。

如本地现状显示上述解释与实际工作流存在冲突，停止对应清理动作并报告，不自行改换“最新实现分支”。

# Part IV — Worktree handling without deletion

## 9. Worktrees to keep active

最终正常工作区只保留两个活跃 Git worktree 角色：

~~~text
A. canonical main
   HEAD = 36bb556441dedd760ab363f3df4f38872bbfc93f

B. latest implementation branch
   codex/session-c-timeout-variable-round-20260917-214638
   HEAD = d9daa2d7af6bb8341349e405433824e89e42bcd4
~~~

如果 Session C 当前没有单独 local worktree，不要求为了形式创建一个；“保留”可以是保留 local branch ref + 需要时可 checkout。优先保持本地目录数量最少。

---

## 10. Historical worktrees

对于 A/B/D、physical-round、START、旧实验/诊断等 historical worktree：

只有在以下全部成立时才可进入 pending-delete 整理：

~~~text
tracked clean
no local unique commits
remote provenance exists
no protected local-only assets remain
~~~

不得使用 git worktree remove，因为它会删除目录内容。

推荐方式：

1. 如 worktree checkout 的 branch 需要保留 local ref，先记录 branch/SHA。
2. 如该 branch 本地 ref 后续准备清理，可先在 worktree 中切到 detached HEAD：
   git -C "<worktree>" switch --detach
3. 使用：
   git worktree move "<worktree>" "<repo>\_pending_delete\20260918-192023\worktrees\<name>"
4. 保持它仍为 registered worktree，等待用户检查并自行删除。
5. 不运行 git worktree prune 处理这些待删除 worktree。

最终报告中将这些列为：

~~~text
QUARANTINED_WORKTREE_AWAITING_USER_DELETE
~~~

用户之后手工删除目录后，另行运行 git worktree prune 即可。本任务不执行该最终删除动作。
