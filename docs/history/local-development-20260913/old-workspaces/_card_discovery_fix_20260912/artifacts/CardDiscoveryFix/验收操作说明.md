# 实机验收操作说明（CONFIG-ACK 动态发现修复版）

## 背景

上一版本把 ICMP/ARP 可达直接当作采集卡，导致台式机本机地址 192.168.0.10（Mellanox ConnectX-5 Adapter #2，接口 down）被误识别为第 5 张卡。本版本改为：只有本次发现会话内返回 60 字节 CONFIG 确认报文的候选 IP 才能成为采集卡。

## 环境要求

1. 台式机保持当前双口 Mellanox 配置，其中一个接口仍保留 192.168.0.10，活动采集接口为实际配置地址。
2. 四张真实采集卡上电并连接（192.168.0.2–.5）。
3. 不需要管理员权限；不要在发现或监听期间运行其他占用 UDP 8000/8080 的程序。

## 验收步骤

1. 双击"启动示例.cmd"或直接运行 PAimageReceiverDiagnostics.exe，不使用 --target-ips。
2. 点击"开始监听"。预期日志顺序：
   - "开始动态发现：候选 192.168.0.2 起 32 个地址…"；
   - "发现参数：ACK 窗口 2000ms × 最多 5 轮，末轮宽限 500ms（总等待上限约 10.5 s）"；
   - 发现结果统计：候选数、本机地址排除数、CONFIG 已确认卡数、超时数、发送失败数；
   - 每张已确认卡一行"✅ 采集卡确认：<IP>（第 N 轮确认，首次发送到确认 X ms，重复确认 Y 次）"。
3. 每次检查以下各项：
   - 192.168.0.10 被记录为本机地址并排除（诊断事件 discovery.local_address_excluded），未收到 CONFIG；
   - .2–.5 各自至少收到一个合格 60 字节发现确认（discovery.card_verified）；
   - 最终目标数稳定为 4，监听启动目标来源为 config_ack_discovery；
   - NCards 写回 4；
   - 正式监听成功绑定。
4. 点击"开始测量"：四卡应再次完成正式 CONFIG 确认后进入测量（发现确认不替代正式配置状态机）。
5. 重复"开始监听—停止监听"至少 5 次，每次重复第 3、4 步。
6. 如需模拟慢响应：将 Discovery/AckWindowMs 临时调低（如 800）或断开某卡再恢复，确认第一轮未响应的卡在后续发现窗口中被接纳（日志显示第 2/3 轮确认）。
7. 通过"导出诊断日志…"导出诊断 ZIP，报告应包含每个候选的最终分类、每张卡首次确认延迟和确认轮次。

## 判定标准

- 通过：5 次循环全部满足第 3 步各项；无"卡5配置确认失败"。
- 发现失败（无任何卡确认）时：程序恢复按钮、保持未监听、不修改 NCards，并给出原因。

## 已知限制（软件测试无法覆盖的部分）

1. 当前协议没有已确认的事务号或硬件唯一标识字段，无法严格区分同一 IP 的旧 CONFIG ACK 与本次 ACK；本实现以"本次发送后的发现窗口内收到 60 字节反馈"作为接纳约束。如后续能从硬件协议或真实报文证明 ACK 存在固定头、回显或校验字段，可再增加内容验证（本版本不凭猜测发明字段）。
2. 本包的软件测试使用 Windows 回环 127.0.0.2–.5 模拟四个不同源 IP 的候选卡，不能证明真实硬件发现成功；真实四卡验收只能由用户在实机完成。
3. 集成测试无法在回环上覆盖"多源 IP + down 接口本机地址"的真实组合；本机排除逻辑由确定性状态机测试与实机日志共同验证。
