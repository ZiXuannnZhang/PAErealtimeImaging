# 1. 新的产品决策与风险授权

当前优先级调整为：

1. **台式机端是项目生产兜底，优先保证正常使用。**
2. 台式机当前已实现稳定零丢包采集，但控制 FPGA 在每个物理采集轮次开始会产生 1 个额外首控制 trigger；该行为已经破坏 4000 有效 A-line 的轮次判定、保存落盘边界、实时成像出帧计数和图像 reset 计数。
3. 因此必须先解决 `4001 physical -> 4000 logical` 的生产语义。
4. 笔记本端启动段 ingress 丢包是下一阶段独立问题。后续该问题仍以**未引入本功能**的 START 候选 `codex/start-admission-fence-fix-20260913-003112@6313540f...` 为诊断基线，不要求本分支兼容所有笔记本丢包分析语义。
5. 用户明确接受以下风险：若笔记本端真实 control trigger 已在 ingress 前丢失，则本功能仍可能把软件看到的第一条真实 scan trigger 当作 control 丢弃；该损失对当前笔记本故障识别是可接受的。

因此，本任务不再要求 wire-level control identity。

# 2. 本任务采用的 Operational Contract

将以下规则视为本分支的产品契约，而不是 FPGA wire protocol 事实：

```text
每个 physical round 开始时存在 1 个额外 control trigger。
该 control trigger 不属于有效 A-line。
每圈有效 logical scan trigger 数来自现有配置（当前典型值 4000），禁止硬编码 4000。
```

软件采用：

```text
每个 round boundary 后，软件看到的第一个 distinct physical trigger identity
= OperationalStartupControl
= 从生产 save/Ring logical path 过滤。
```

这里的 `first visible` 是用户明确授权的 operational heuristic。

若真实 control 已在 ingress 丢失而导致第一条 scan 被误过滤，这是已接受风险；必须通过诊断字段明确可见，不得伪装成网络丢包或 physical trigger 不存在。

# 3. 目标状态机

建议实现共享 `PhysicalRoundNormalizer` 或等价组件，状态至少表达：

```text
AwaitingControl
CollectingScan
```

并维护：

```text
measurementSession
roundGeneration
configuredLogicalTriggersPerRound
logicalDistinctCount
recent physical-trigger decisions
last observed physical-trigger time
```

## 3.1 Measurement 开始

新 measurement session 开始时：

```text
state = AwaitingControl
logicalDistinctCount = 0
```

下一条**新的 distinct trigger identity**被分类为 `OperationalStartupControl`。

该 identity 在所有卡上必须得到相同 decision。

## 3.2 Control 过滤后

过滤首 control identity 后：

```text
state = CollectingScan
logicalDistinctCount = 0
```

下一条新的 distinct trigger identity 分配：

```text
logicalTriggerIndex = 0
```

之后依次推进到：

```text
logicalTriggerIndex = configuredLogicalTriggersPerRound - 1
```

## 3.3 Count boundary

当本轮已确认 `configuredLogicalTriggersPerRound` 个 distinct logical trigger identity 后：

```text
roundCompleted = true exactly once
next unseen distinct trigger -> OperationalStartupControl
```

下一轮无需新的软件 START。

注意：最后一个 logical trigger 的其它卡可能稍后到达；它们仍必须通过 decision cache 得到上一轮同一个 logical index，不能因 round 已完成而被误判为下一轮 control。

## 3.4 Timeout boundary

发生现有配置定义的无触发 timeout 时：

```text
清理当前 partial logical round / Ring partial block / reconstruction round state
state = AwaitingControl
logicalDistinctCount = 0
```

下一条新的 distinct trigger 作为 `OperationalStartupControl` 过滤。

如果 count boundary 后已经处于 `AwaitingControl`，随后又发生 timeout，不得生成空 round、重复推进 generation 或重复 reset 业务状态。

# 4. Physical Trigger Identity / 多卡一致性

当前生产数据只有 `uint16 triggerSeq` 可共享使用。本文授权在本产品 operational model 中以：

```text
measurementSession + active round context + uint16 triggerSeq
```

作为 shared physical trigger identity 的核心依据，并配合有界 recent-decision cache 处理：

```text
同一 trigger 跨卡乱序
迟到卡
triggerSeq wrap
round boundary 前后的旧 decision
```

要求：

- 第一个到达某 identity 的卡可以创建 decision；
- 其它卡同 identity 必须复用同 decision；
- logical count 对同 identity 只能推进一次；
- control identity 在所有卡均为 control；
- 某卡未收到 control identity 时，不要求人为生成该卡的 control group；
- 如果所有卡都未收到真实 control，则下一可见 scan identity 会被作为 control 过滤，这是本文明确接受的风险；
- 不允许每个 `DataProcessor` 自己维护独立 first-trigger counter。

不得把裸 `triggerSeq` 作为跨 measurement session 的永久 key。

---

# 5. Classification 与完整性无关

Control/scan 分类依据是 round state + first visible distinct identity，而不是 TriggerGroup 是否 complete。

因此首可见 identity 即使只形成 partial TriggerGroup，也仍应在生产 logical path 中被作为 control identity 过滤；其底层 physical packet-loss/partial 统计必须保持真实。

如果真实 control 完全不可见，则不会产生 control group；此时下一可见 scan 被过滤，属于已接受 operational 行为。

# 11. 必须测试的场景

## T1 — 台式机目标：1 + N -> N

用配置 N（至少测试 N=4000，以及一个小 N fixture）：

```text
1 visible control + N scan
```

断言：

```text
physical distinct = N+1
control filtered = 1
logical accepted = N
save = N
Ring = N
roundComplete exactly once
```

## T2 — 连续多轮、同一 measurement session

至少 3 轮：

```text
(control + N scan) x 3
```

不插入新的软件 START。

断言：每轮均只保存/成像 N 条；每轮首 control 被过滤；round generation、block/frame/reset、auto-save 边界严格对齐。

## T3 — Count boundary 后跨卡迟到

第 N 个 logical trigger 的部分卡先到导致 round complete，另外卡随后到达同 trigger identity。

断言：迟到卡仍得到上一轮相同 logical index，不得被当作下一轮 control。

## T4 — 多卡乱序

同一 trigger identity 按不同 card 顺序并发到达。

断言 classification/index 一致，logical count 只推进一次。

## T5 — First visible partial control

首 control identity 至少一张卡形成 partial TriggerGroup。

断言：生产 save/Ring 不接收；raw partial/loss accounting 保留。

## T6 — Control 在部分卡完全不可见

其它卡已建立 control decision，但某卡没有该 trigger。

断言：该卡的下一 scan 不因本卡“first observed”再次被过滤；shared decision/round state 必须避免 per-card double filtering。

## T7 — Control 在所有卡完全不可见（显式接受风险）

输入只有 N 个真实 scan trigger。

按本文 operational policy，第一条可见 scan identity 会被过滤。

断言：

```text
controlFiltered = 1 (basis first-visible-operational)
logicalAccepted = N-1
不得伪造缺失的第 N 条
不得把该软件过滤记为网络丢包
```

这是**预期行为测试**，不是失败。

## T8 — Timeout partial round

收若干 logical scan 后超时，再开始新 round。

断言：旧 partial round 清理；下一 first visible identity 过滤一次；Ring/reconstruction reset exactly once。

## T9 — Count boundary + timeout 双边界

完整 round 已 count-complete 后进入 idle 超时，再开始新 round。

断言：不得生成空 round、double generation 或 double business reset；下一 round 仍只过滤一次 control。

## T10 — uint16 wrap

覆盖 `65534, 65535, 0, 1` 附近并跨卡乱序。

断言 recent-decision cache 和 round state 不因 wrap 错分类。

## T11 — 保存/Ring 一致性

对每个 logical round 断言：

```text
save logical identities == Ring logical identities
```

不能只比较总数。

## T12 — 现有 START/session regression

重新执行原任务指定的 START fence、session transaction、batch、Ring assembler 等回归；当前 START admission 语义不得变化。
