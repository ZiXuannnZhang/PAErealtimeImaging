# 1. 用户确认的产品语义

前端“环形扫描参数设定”中的：

```text
超时重置(0=关闭)
```

对应 `RingReconCudaConfig.timeoutResetSec`，是本任务 physical-round normalizer 的**唯一物理轮次无触发超时参数**。

例如前端设置：

```text
timeoutResetSec = 2.0 s
```

正确语义为：

```text
同一 measurement session 内
当前 physical round 尚未通过 logical count 完成
        ↓
连续 2.0 s 没有新的 distinct physical trigger
        ↓
上一 partial physical/logical round 结束
        ↓
清理 partial logical/Ring/reconstruction round state
        ↓
下一条可见 distinct physical trigger
= 新一轮 OperationalStartupControl
= 从 save / Ring logical path 过滤
        ↓
再下一条 logical scan 从 index 0 开始
```

`timeoutResetSec == 0` 表示：

```text
关闭 physical-round idle timeout
```

此时只有 count boundary 能结束正常 logical round；不得使用其它内部固定 timeout 替代。

---

# 2. Count boundary + timeout boundary 双边界模型

本功能的物理轮次判定必须统一为：

```text
A. Count boundary
configuredLogicalTriggersPerRound 个 LogicalScan 已完成

或

B. Idle timeout boundary
CollectingScan 状态下无新的 distinct physical trigger 超过 timeoutResetSec
```

任一边界成立后：

```text
当前 round 结束
→ normalizer 进入 AwaitingControl
→ 下一 visible distinct trigger 过滤为 OperationalStartupControl
→ 后续 logical index 从 0 开始
```

如果 count boundary 已经完成并进入 `AwaitingControl`，随后又经过 timeout：

```text
不得再次推进 roundGeneration
不得产生空 round
不得重复业务 reset
不得重复统计 timeout boundary
```

即 count-complete + idle 必须幂等。

---

# 3. 当前错误实现 — 必须修正

当前 `SourceCore::Decision::Timeout` 是 **单卡 active trigger assembly timeout**：某卡某个 trigger 已收到部分 packet，但在内部固定约 100 ms 内没有收齐，于是关闭该 partial assembly。

它表示：

```text
single-card / single-trigger packet assembly timeout
```

它**不是**：

```text
physical round no-trigger idle timeout
```

因此必须删除/禁止如下生产语义：

```text
Decision::Timeout
    → PhysicalRoundNormalizer::timeoutBoundary()
```

不论该 partial trigger 当前被分类为：

```text
OperationalStartupControl
或
LogicalScan
```

`SourceCore::Decision::Timeout` 都不得自动结束整个 physical round。

保留它原有职责：

```text
partial trigger / packetsDropped / assembly diagnostics
```

不得修改或伪造这些低层统计。

---

# 4. 正确的 timeout 来源

必须把：

```text
RingReconCudaConfig.timeoutResetSec
```

作为 physical-round normalizer 的 canonical timeout source。

当前 UI 文案和 tooltip 已定义其产品含义：

```text
0=关闭；真实采集中未采满整圈即停机时，超过该秒数无新触发后，下一触发判定为新一圈并重置旧图像。
```

不得再引入另一个固定 100 ms、500 ms、1 s 或其它 guessed round timeout。

如果已有多个对象保存该数值，必须明确 single canonical value，并保证：

```text
前端 Apply/OK 后
→ 当前 production normalizer 使用相同 timeoutResetSec
→ RingBlockAssembler / auto-save timeout 逻辑使用相同 timeoutResetSec
```

如果 normalizer 同时控制 FileSaver 与 Ring，timeout 配置传播**不得依赖实时成像 worker 是否已经启动**。即使 Ring service 暂时关闭，只要当前 PAimage physical-round normalization 正在使用，该配置也不能静默退回其它 timeout。

# 5. 推荐实现时序

推荐让 normalizer 在分类“新的 distinct physical trigger identity”之前检查 idle gap。

伪代码语义：

```text
classify(newIdentity, observedMonotonicTime):

    if state == CollectingScan
       and timeoutResetSec > 0
       and havePreviousDistinctTrigger
       and observedMonotonicTime - lastDistinctTriggerTime >= timeoutResetSec:

        apply PhysicalIdleTimeoutBoundary exactly once
        state = AwaitingControl
        logicalDistinctCount = 0
        roundGeneration += 1
        emit TimeoutBoundary

    # 先处理 timeout，再分类当前 identity
    if state == AwaitingControl:
        current identity = OperationalStartupControl
        filter from save/Ring
    else:
        current identity = LogicalScan

    update lastDistinctTriggerTime only for a genuinely new physical identity
```

关键要求：

> physical timeout 必须在“下一轮首 trigger”的 classification 之前生效。

禁止：

```text
当前 trigger 已经作为 LogicalScan 进入 FileSaver/Ring
→ RingBlockAssembler 后来才发现 idle
→ 再 reset
```

否则首 control 已经泄漏到生产数据。

---

# 6. 时间来源要求

使用 monotonic time，不使用 wall-clock。

优先复用当前 PAimage frame/ingress 已有的 monotonic timestamp；如果实现选择在 HostOutput classification 时取 `SocketReceiver::now()`，必须说明原因并保证跨卡/线程一致性足以支持 timeout 语义。

同一 physical identity 的跨卡迟到重复不得更新 `lastDistinctTriggerTime`。

只有 normalizer 首次观察到一个新的 distinct physical trigger identity 时，才允许推进该时间锚点。

因此：

```text
late card of old trigger
```

不得人为保持 round“活跃”，也不得触发新的 timeout 判断。

---

# 7. Normalizer 配置接口

`PhysicalRoundNormalizer` 应明确拥有或读取：

```text
configuredLogicalTriggersPerRound
timeoutResetSec / timeoutResetNs
```

配置必须支持：

```text
0 = timeout disabled
>0 = enabled
```

运行期更新 timeout 配置时：

- 不得把配置更新本身当作 physical round boundary；
- 不得因为从 2.0 改到 3.0 就无条件过滤下一 trigger；
- 如果产品现有配置流程要求在下一轮/下一 measurement 才生效，应明确采用该策略并记录诊断；
- 不允许 silent fallback 到 SourceCore 100 ms。

---

# 8. Ring / Save / Auto-save 对齐

physical timeout 是 shared logical round boundary，不是 Ring-only event。

必须保证同一 timeout boundary 下：

```text
PhysicalRoundNormalizer partial logical state reset
FileSaver 下一有效 scan 属于新 round
Ring partial block reset
wavelength/angle phase reset
reconstruction ring_reset exactly once
auto-save generation / next directory 与该 physical round boundary 对齐
```

现有 `RingBlockAssembler::timeoutResetSec`、`idleSeconds()`、MainWindow 250 ms timeout timer 可保留，但必须与 shared normalizer 语义一致。

尤其要防止：

```text
normalizer reset 一次
RingBlockAssembler 又因同一 idle 独立 reset 一次
MainWindow timeout callback 再 reset 一次
```

要求同一 physical idle boundary 的业务 reset 最终 exactly once，或明确设计为各层幂等且测试证明不会产生 double generation / double reconstruction reset / double auto-save advance。

现有“超时到点保存 PNG”行为可以继续在 timer 到点时执行；但不能因此让 logical normalizer 使用另一套 timeout 定义。

---

# 9. SourceCore assembly timeout 隔离

新增明确 invariant：

```text
SourceCore Decision::Timeout
!=
PhysicalRoundEvent::TimeoutBoundary
```

场景：

```text
round 正在 CollectingScan
某卡某 trigger 收到部分 UDP
100 ms 后 assembly timeout
其它卡/后续 trigger 继续
```

要求：

```text
normalizer roundGeneration 不变
normalizer state 仍按 physical idle 时间决定
下一新的 distinct trigger 不得仅因该 assembly timeout 被过滤成 control
SourceCore partial/loss 统计保持真实
```

# 10. Required Tests

## T1 — Production physical idle timeout（核心）

同一个 measurement session，不重新 START：

```text
control
+ M 个 logical scan，M < N
+ idle > timeoutResetSec
+ next control
+ N 个 logical scan
```

要求：

```text
第一次 control filtered
M 个 scan accepted
idle boundary exactly once
旧 partial round reset
next control filtered
新 round logical index = 0..N-1
save / Ring identities 一致
round generation 正确推进
```

测试必须走接近真实 production 接线，不能只直接调用：

```cpp
normalizer.timeoutBoundary(...)
```

来伪装通过。

## T2 — timeoutResetSec == 0

同一 session：

```text
control + partial scans
+ 很长 idle
+ next trigger
```

要求：

```text
不发生 physical idle timeout boundary
不因 idle 自动 AwaitingControl
下一 trigger 按当前 CollectingScan 继续 logical count
```

## T3 — 单卡 100 ms assembly timeout 不得结束 round

通过 SourceCore/HostOutput production path 构造：

```text
正常 round CollectingScan
某卡一个 trigger partial
等待 > SourceCore assembly timeout
产生 Decision::Timeout
随后新的完整 distinct trigger 到达
```

要求：

```text
PhysicalRoundEvent::TimeoutBoundary count 不变
roundGeneration 不变
下一完整 trigger 为 LogicalScan，不是 OperationalStartupControl
packet-loss / partial counters 正确增加
```

## T4 — Count boundary + idle timeout 幂等

```text
control + N logical scan
→ count complete
→ idle > timeoutResetSec
→ next control + scans
```

要求：

```text
CountBoundary exactly once
idle 不产生第二个空 round boundary
roundGeneration 不 double advance
reconstruction reset / auto-save generation 不 double advance
next control 只过滤一次
```

## T5 — 跨卡迟到不刷新 idle 锚点

```text
identity X 首卡到达
若干时间后 X 的迟到卡到达
```

要求：

```text
lastDistinctTriggerTime 仍对应 X 第一次成为新 distinct identity 的时间策略
迟到卡不作为新的 physical activity identity
```

随后制造超过 timeout 的新 identity，确保 boundary 判定正确。

## T6 — 跨 uint16 wrap + timeout

覆盖：

```text
65534, 65535, 0, 1
```

并在 partial round 中插入 idle timeout。

要求 cache / generation / identity 仍正确。

## T7 — Save/Ring/auto-save timeout consistency

使用小 N fixture，验证一个 partial round timeout 后：

```text
旧 partial save/ring boundary 不泄漏到新 round
next control 不保存/不进 Ring
next scan 从 logical index 0 开始
Ring reset exactly once
auto-save generation 不 double advance
```

如果完整 GUI auto-save 难以在单测中驱动，至少提供可注入 seam，并对 production callback wiring 做集成测试。
