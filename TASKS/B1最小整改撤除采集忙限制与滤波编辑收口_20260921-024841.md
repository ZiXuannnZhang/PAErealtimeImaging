## 4. 按顺序执行的修改步骤

### 步骤1：删除采集busy及内部启动例外

1. MainWindow删除本轮新增的isAcquisitionBusy声明和定义，以及ensureRingConfigDialog中的setAcquisitionBusyPredicate注入。
2. RingConfigDialog删除setAcquisitionBusyPredicate、对应成员、applyConfig中的采集busy判断。
3. 删除applyConfigForRealtimeStart声明和实现。保留一个正常applyConfig/validateAndSubmit路径。
4. onRealtimeImagingToggled改回调用正常applyConfig，并继续检查bool结果；应用失败不得启动馈送或服务。
5. 保留ImagingController::isBusy和configureRing现有非致命拒绝、2014分流。不要恢复原自动重启链路。

预期：采集正在进行而成像停止时可以应用参数并启动成像；成像运行时不能应用新参数。

### 步骤2：仅保存六个滤波字段的已确认值

在RingConfigDialog内增加一个小结构（不包含整个RingReconCudaConfig）：

```
ConfirmedFilterValues {
  bool hpOn, lpOn;
  double hpMhz, lpMhz;
  int hpOrder, lpOrder;
}
```

实现两个简单成员函数：
- captureConfirmedFilterValues()：从六个控件读入上述成员。
- restoreConfirmedFilterValues()：把该成员写回六个控件；允许作为MainWindow调用的恢复接口，但不提交配置、不调用controller、不保存settings。

更新时机必须严格如下：
1. 构造函数完成buildUi与首次restoreDefaults后，capture一次。这样第一次启动使用加载的默认值；无保存键则两滤波关闭。
2. applyConfig经校验且controller.configureRing返回true后，capture一次。失败不得capture。
3. 点击“恢复默认”只修改待编辑控件，不capture；点击“设为默认”只保存settings，不capture、不应用。明确提示“保存为下次启动默认值，当前配置未应用”即可，不新增弹窗流程。
4. 重写对话框reject()：先restore六个值，再调用QDialog::reject()。确保取消按钮、Esc、标题栏关闭均走该路径；不要触碰其余旧环形参数的历史语义。
5. MainWindow在启动实时成像路径，调用setAcquisitionParams后、正常applyConfig前，先调用restoreConfirmedFilterValues()。这是恢复六个已确认值，不是绕过校验的提交例外；随后仍走正常applyConfig和controller busy检查。

说明：步骤5保证先前“应用被拒但控件仍有草稿”也不会在下一次启动时被带入；只解决B1新增六字段，不引入整套配置快照或通用事务框架。

### 步骤3：修正新增启动失败分支的UI状态

onRealtimeImagingToggled(true)中若applyConfig失败：
- 不调用configureRingAssembler/startRingFeedWorker/startSvc；
- 保留现有诊断记录；
- 用QSignalBlocker把实时成像勾选恢复为false，恢复按钮可操作状态；
- 不修改采集/原始保存，不触发自动重试。

不要对正常成像运行中被拒的配置走上述“启动失败”逻辑。现有onImagingConfigRejected只提示，不动ready/使能/轮次/馈送，原样保留。
