# 诊断日志导出

## 日常日志与诊断模式

运行日志正文固定高度，可内部滚动；下方「导出日志」按时间范围生成 ZIP。「诊断模式」
每次打开程序默认不勾选，变更在**下一次开始监听**时生效，不打断正在进行的采集。
日常保留配置、收包/缺口与保存计数、轮次边界、成像队列及重建状态。需要逐包复现时先勾选，
再重新开始监听：详细 trace、timing 和接收循环窗口最多记录本次监听前 15 分钟，
也受各流容量上限约束。空间不足时记录日常日志并提示详细诊断未启用。

| 程序自管文件 | 保留方式 |
| --- | --- |
| `bin/app_log.txt` | 每段 8 MiB，保留当前及最近 3 份历史；旧的超大追加日志仅保留最近尾部 |
| `bin/paimage-diagnostics` | 结构化历史每次运行保留当前和上一段，每段合计约 16 MiB；普通历史按 7 天、30 次已结束运行及 500 MiB 配额清理 |
| `bin/paimage-traces` | 以监听为单位，启动和结束时清理旧记录；目标总量 2 GiB、7 天、64 次监听；详细模式提前为当前监听预留最多 1.5 GiB |

进行中的监听、正在导出的记录、旧系统抓取及无法识别为程序自管的目录不会自动删除；
多实例或长时间导出时清理可能延后。崩溃转储、原始采集文件、`recon_png`、用户导出的 ZIP 和已有现场证据
均不属于自动清理对象。导出包注明容量轮转、时间窗裁剪及其他可能的记录缺口。

「导出日志」在后台按同一时间窗和固定序号边界选取 trace、timing 和接收循环记录，并使用标准
ZIP Deflate 压缩大条目；只有 timing 或接收循环记录的监听也有独立清单。旧 ZIP 可继续用原有分析器读取。
常规交付已移除「实验标记」和「准备系统抓取」；人工说明请填写导出对话框中的「现场说明」。
新程序不创建系统抓取请求或 Pktmon/WPR 会话；仓库保留历史抓取工具与离线分析器用于旧证据追溯。


本功能用于保存 PAimage 生产采集链的可追溯运行证据。当前程序是
`PAimageReceiverDiagnostics.exe`；项目整体状态以根目录 `PROJECT_STATUS.md` 为准。

## 使用方式

在主窗口“运行日志”区域选择“导出日志”，选定开始和结束时间，填写可选现场说明并选择 ZIP 保存位置。

故障发生后应尽量及时导出。停止监听后仍可导出；重启程序后也可以选择已持久化的历史运行。
导出本身不重新扫描网络、不发送 CONFIG/START/STOP。

## 导出内容

典型 ZIP 包含：

| 文件 | 用途 |
| --- | --- |
| `summary.txt` | 人类可读摘要和完整性提示 |
| `runtime.log` | UI / Qt / startup 日志 |
| `events.jsonl` | 带时间、session/correlation 的结构化事件 |
| `network.json` | 记录时本机网络快照 |
| `settings.json` | 当次参数/诊断状态 |
| `manifest.json` | 导出边界、格式、校验与完整性 |

实际字段以当前 executable 生成的 manifest/schema 为准。

## 证据边界

- target/card 编号是本地目标列表位置，不自动证明设备类型；
- ARP/可达性、18 字节 ready、60 字节 CONFIG ACK 是不同证据；
- `sendto` 成功只证明本机发送调用成功；
- 应用 trace 无法替代 wire/NIC/driver 层抓包；
- 日志缺失、轮转、写盘失败或异常退出会降低证据完整性。

基本判读：

```text
wire/pktmon 有包，但 stage 1 无包
  -> NIC / driver / socket / receiver 继续定位

stage 1 有包，stage 2 admission/source 丢弃
  -> 应用 session / START / SourceCore 边界

SourceCore 完成，但 save/sync/imaging 缺失
  -> 对应下游 queue / FileSaver / ImagingBypass / Ring 路径

wire 侧也无包
  -> 继续向 FPGA / 控制系统 / 网络侧取证
```

## 当前状态说明

诊断系统是观测工具，不改变采集协议和 round policy。

A/B/C/D 当前实机验证范围已通过，但底层额外 startup trigger 的精确 FPGA/LabVIEW 来源仍未证明；
因此历史报告中的“待真机验证”“卡五”“4001”等阶段性描述不能直接作为当前项目状态。
