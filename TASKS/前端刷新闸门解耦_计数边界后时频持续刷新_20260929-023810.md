## 0. 已钉定的代码事实（分析代理 2026-09-29 逐文件核实于环形增强分支 tip `69af295` = 本任务分叉点，免推导，直接采用）

1. **冻结闸门执行点 = `HostOutput::sync()`**（`src/PaimageAcquisition/HostOutput.cpp:92-116`）。当前逻辑：对同步组内每帧分类后，三种条件任一命中即 `filter=true`，随后 `if(filter) return;` —— 发生在 `workers_.pushSync(...)` **之前**，整组不进 OutputQueues。三种条件：
   - `decision==OperationalStartupControl`（启动控制触发）；
   - 过期轮次帧（`measurementSession==timeoutSession_ && roundGeneration<timeoutGeneration_`）；
   - **计数边界**：`disableCountBoundary()==true && decision==LogicalScan && logicalTriggerIndex>=0 && logicalTriggerIndex>=configuredLogicalTriggersPerRound()`。
   时域/频域信号窗口与实时成像窗口共用 sync 这一个前端入口，因此同时冻结；保存走 `setDirectSaveSink`（构造器 `:50` 一带接线，card 路径独立），故保存照常。
2. **下游分叉点 = `DataProcessor::deliverAssembled`**（`src/DataProcessor.cpp:435-490`）：`frontend==true` 时先 `m_framePublisher->submit(group)`（成像路径：ImagingBypass/Ring），后 `m_frontendSubmitSink(group)`（前端信号路径：FrontendPreprocessor→DisplayBuffer→时域/频域窗口）。两者对同一 group 独立消费（前端侧在 stage worker 内 deep copy）。**跳过前者、保留后者即实现解耦。**
3. **SyncFrame 流转链**：`HostOutput::sync` → `OutputWorkers::pushSync(trigger, frames, startupRelease)`（`include/PaimageAcquisition/OutputWorkers.h:37`）→ `OutputQueues::pushSync` 构造 `SyncFrame{trigger, session, block, index, cards}`（`OutputQueues.cpp:17-26`；`SyncFrame` 定义 `OutputQueues.h:11-15`，**当前不含任何分类信息**）→ sync worker 经 `syncSink_` 回调 `HostOutput::consumeSync`（`HostOutput.cpp:139-163`）→ `deliverAssembled(group,false,true)`。消费端无法自行判定超界，**须显式传标志**。`FrameConverter` 的分类打标存 side-table 且无回读 API（`include/PaimageAcquisition/FrameConverter.h`），不走它。
4. **分类器两模式**（`PhysicalRoundNormalizer.cpp:203-218`；UI = `RingConfigDialog.cpp:286-292`「禁用计数重置」勾选框，出厂不勾选）：
   - 不勾选（`disableCountBoundary=false`）：第 N 个逻辑触发产生 CountBoundary——`roundComplete`/`isFinalLogicalTrigger` 置位、`resetCurrentRoundLocked()`、`roundGeneration++`。无冻结。`roundComplete`/`isFinalLogicalTrigger` **仅**在该分支产生。
   - 勾选（`true`）：**永不计数重置**（tooltip：「物理轮次继续，直到超时重置」）；超界触发同 roundGeneration、`logicalTriggerIndex` 继续递增，交由事实 1 的闸门过滤——即现冻结来源。
5. **解冻路径**（勾选模式、现行为）：仅物理轮次超时空闲（`TimeoutBoundary`，`PhysicalRoundNormalizer.cpp:160-176`）或停止/重启监听。本任务不改变该轮次语义：超界帧 `tagNormalization` 携带的仍是同一（已停滞）roundGeneration。
6. **测试基建**：`tests/paimage_host_output_test.cpp` 已有 HostOutput+FrontendPreprocessor+DisplayBuffer 全接线与 `displayUpdates` 计数断言范式（`makeFrontend`/`wireFrontends`），是本任务新契约断言的自然落点；`tests/count_boundary_save_binding_test.cpp`、`tests/round_policy_settings_test.cpp` 覆盖计数边界保存绑定与策略持久化。main 与分叉点的 `HostOutput.cpp` **逐字节相同**（机制同构；基底已裁定为环形分支 tip 的新建分支）。
7. **计数器口径**：超界触发当前照常进入 ingress 统计（闸门在统计之后的 sync 入口），卡片状态「已采集/跳号/触发丢弃」口径不受本任务影响，须保持。

## 工作一：计数边界过滤三态化（仅勾选模式行为变化）

### 1.1 语义定义（三态）

| 态 | 条件 | 行为 |
| --- | --- | --- |
| **Drop** | `OperationalStartupControl`；或过期轮次帧 | 整组丢弃（现行为逐字保留，任何模式下都不进前端/成像） |
| **FrontendOnly**（新增） | `disableCountBoundary()==true && LogicalScan && logicalTriggerIndex>=0 && logicalTriggerIndex>=configuredLogicalTriggersPerRound()` | **不再整组丢弃**：进前端信号路径（时域/频域持续刷新），**跳过成像发布器**（实时成像保持冻结） |
| **Pass** | 其余 | 现行为逐字保留 |

同组内多帧混合时沿用现组级判定口径：任一帧命中 Drop 仍整组丢弃（优先级最高）；否则任一帧命中 FrontendOnly 则整组按 FrontendOnly 处理。

### 1.2 实现落点（新增尾参一律带默认值，既有调用点零改动）

1. `include/PaimageAcquisition/OutputQueues.h`：`SyncFrame` 增字段 `bool beyondCountBoundary = false;`；
2. `OutputQueues::pushSync` / `OutputWorkers::pushSync`：增带默认值的尾参并透传到 `SyncFrame`；
3. `HostOutput::sync`：按 §1.1 三态改写 filter 判定（实现形式自选——分离两个布尔或等价枚举——语义必须与上表等价），`pushSync` 透传超界标志；
4. `HostOutput::consumeSync`：把 `SyncFrame::beyondCountBoundary` 传给 `deliverAssembled` 新尾参 `bool imagingSubmit = true`；
5. `DataProcessor::deliverAssembled`：`imagingSubmit==false` 时跳过 `m_framePublisher->submit(group)`（`publisherAccepted` 保持 false），`m_frontendSubmitSink(group)` 照常执行；
6. **诊断留痕**：超界组在 stage-7 trace 自然呈现 `frontendAccepted=true, publisherAccepted=false` 新组合（既有 observe(7,1/2/3) 不动）。执行代理在证据中写明该组合作为「count-boundary frontend-only」的判定方式即可；若最小 diff 内可在 looplog/trace 增加显式标记则做，不可则不做，均须如实记录。
