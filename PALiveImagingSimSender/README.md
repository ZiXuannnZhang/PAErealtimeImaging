# PALiveImagingSimSender — UDP 数据发送模拟器

用于交付包 `PALiveImaging/delivery` 中监听程序的**同机 UDP 联调验收**。
带前端页面，一键启动数据发送。

## 运行

直接运行 `bin\PALiveImagingSimSender.exe`，无需安装。

## 使用步骤

1. 启动交付版监听程序（同机联调模式）：
   ```
   PALiveImaging\delivery\bin\MC410T_Receiver.exe --target-ips 127.0.0.1,127.0.0.2,127.0.0.3,127.0.0.4
   ```
   （每张虚拟卡使用一个独立回环源 IP：127.0.0.1 ~ 127.0.0.4，监听程序按源 IP
   映射卡号。若沿用单个 `--target-ips 127.0.0.1`，就绪包只会让卡1上线，其余卡
   只能等待 ARP 兜底探测，因此推荐上面的 4 个 IP 写法。）
2. 在监听程序中：打开“环形扫描控制台”→ 点击“启动环形重建”；
   回到主窗口点击“开始监听”。
3. 打开本模拟器，选择数据文件（默认 `D:\zzx\data\20260519\14.dat`）、
   数据集（14.dat=360° / 11.dat=180°）、位宽（32/16）、
   发送速率（默认 40Hz，真实 A-line 速率；0=最快）、
   采集时间（默认 20000ns，与监听程序“采集时间(ns)”保持一致）、
   模拟数据采样率（默认 200MSa/s）、监听程序采样率（默认 200MSa/s，
   需与监听程序“采样率”一致；后续版本改为自动读取监听程序下发值）、
   起始端口（默认 8001）。
4. 勾选“发送通道”：只有勾选的通道发送真实信号，未勾选通道发送随机噪声
   （噪声幅度 = 该通道信号 RMS 的百分比，默认 10%），监听程序中未勾选通道
   应显示噪声而不是信号。
   **扇区聚合**：勾选的通道数决定扇区分配。勾选 C 个通道时，每个通道聚合
   8/C 个源扇区并发送 8000/(C×2) 根 A-line/波长，对应“按勾选通道数均分 360°”
   （例：勾选 2 个通道 → 每通道覆盖 180°）。请与监听程序“环形扫描参数设定”
   中勾选的通道保持一致（支持 1/2/4/8 个通道）。
5. 需要验证“采集卡上线”时，在“虚拟采集卡”区设置卡数并点击“启动虚拟采集卡”：
   模拟器会从 127.0.0.1~127.0.0.4 周期发送 18 字节就绪包到监听程序端口 8000，
   监听程序日志应显示“卡1~4 FPGA 就绪 ✓”，主窗口网络信息变为“全部4卡就绪 ✓”。
   之后在监听程序下发配置时，模拟器会按卡回发 60 字节配置反馈，使“开始测量”
   流程可手动走通。
6. 点击“开始发送”：按真实采集协议（4 字节头 + B/A 交织载荷，
   8001~8004 端口）回放数据；进度条与日志实时显示。
7. 监听程序“环形扫描控制台”显示“已输出帧 seq=5”即联调通过
   （14.dat 8 通道，每块 200 A-line，共 5 块）。

## 说明

- 回放的是已解调时域数据，接收端按真实采集链路处理（无二次解调）。
- 源数据为 200MHz（5ns/点）、每 A-line 4000 点（20000ns）。发送时按
  “模拟数据采样率 → 监听程序采样率”做线性插值/降采样；当监听程序
  采集时间超过源数据时长时，用该 A-line 第 51~100 点（50 点）循环补齐，
  保证监听端不会因包数不足丢弃整个触发。
- 发送节拍按绝对时刻调度：40Hz × 4000 触发严格 100 秒完成。
- 位宽选择（32/16）只影响 UDP 载荷的量化/削顶与包大小：源文件为 double，
  32bit=int32 完整保留幅值（仅整数截断），16bit=int16 会把超过 ±32767 的
  强信号削顶。成像/环扫验证建议用 32bit，且必须与监听程序数据格式一致。
- 虚拟采集卡仅用于本机（127.0.0.1）监听程序验证；源 IP 固定使用回环地址。
- 速率建议 ≤200 触发/秒；突发发送（0=最快）时接收端显示缓冲可能跳过
  中间触发，属测试节奏问题。
- 停止：点击“停止”即可中断当前发送。

## 源码构建

依赖 Qt 6.8 MinGW、CMake/Ninja。运行 `build.cmd` 构建，产物在 `build\bin`，
手动拷贝到 `bin` 即可。
