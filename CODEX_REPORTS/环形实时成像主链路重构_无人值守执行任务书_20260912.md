## 4. 必须落地的公共契约

### 4.1 数据流与只读身份

    SocketReceiver → SourceCore
      ├─ CardFrame → 独立SaveQueue → SaveWorker → DAT + sidecar
      ├─ 完整同步帧 → 非阻塞成像旁路 → RingPipeline → 位置组块 → 双槽IPC → ImagingSvc → 最新显示
      └─ 轻量描述 → RoundTracker/质量统计（有界，不反压接收）

新增小型身份头、RoundTracker和RingPipeline，不引入通用框架。类型名可随工程规范调整，以下语义固定：

- FrameIdentity：监听会话、16位wireTrigger、展开触发号、卡号、入口ID、首次接收单调时间、配置版本。
- RoundDescriptor：roundId、候选编号范围、判定依据、预期数量、位置置信度、关闭原因。
- FrameQuality：原组包判定、包覆盖、长度校验、采样原点可信度、缺失原因；不覆盖旧统计。
- RingBlock：服务代、轮次、配置代、块号、起始位置、positionCount（1..50）、通道、有效位图、显式波长/角度、raw。
- SaveResult：Accepted、Buffered、Written、Failed及实际字节数，消费返回不再冒充写入成功。
- ImagingSubmitResult：保留已有原因，补充BusySlots、VersionMismatch、StaleGeneration、InvalidPayload。

载荷继续共享只读，不在各线程修改已发布frame，不重新复制全量采样只为附加元信息。RoundTracker为单线程所有者，发布不可变映射/快照；接收线程只投递标量描述。描述队列容量8192，满立即记录metadataDropped并降低相关区间置信度，不等待、不影响采样流。多卡同触发归并。

RoundTracker尚未完成归属时，保存先记wire身份，后写round_assignment事件；成像可按同一会话的稳定相对坐标工作并标记pending/relative，获得新epoch时复位。不能让保存/接收等分类。

### 4.2 自动轮次、未知起点与首触发

1. 使用原接收时间和配置timeoutResetSec判断候选空闲边界。大于0才分段，0保持关闭，不能悄改用户设置。交付独立测试配置设2秒，操作卡轮间至少3秒。
2. UI定时器、保存开关和成像消费时间不再分别定义轮次；统一引用RoundTracker的候选边界。保存关闭不停止识别。
3. 展开16位编号：前进距离小于32768可推进高水位，重复/窗口内迟到不推进；半范围歧义或疑似复位另开unknown epoch，记录原因，不强猜。
4. 空闲只证明接收活动分段。4001预期不用于倒推出没有证据的首尾编号。
5. 默认PositionConfidence=RelativeOnly，首个可见号作为相对0；内部缺口保留跨度。界面写“位置未校准，波长归属待确认”。连续、完整、数量正确不构成物理起点证据。
6. 只有已有明确外部标记或自动测试oracle给出锚点，才可Confirmed；本任务不增加人工输入。无锚点不阻塞预览。
7. startup-policy继续bypass。未知起点不删除首个可见触发。可信的多余触发只在有效重建输入排除，保存仍保留并标记。未知模式4001行和不足50的尾块是合法结果，不能为凑4000行删一行。
8. RelativeOnly预览可以用配置奇偶作为假定波长相位，但必须在图像质量中标记假定。未知转可信时另开成像epoch，禁止重新解释已积分图像。

### 4.3 质量与位置组块

不改SourceCore接收和单卡关闭条件，不新增清socket、预热、延时、recv API替换或接收线程拆分。在下游检查每槽实际长度覆盖预期字节，末槽按剩余有效字节；检查样点和通道长度。保留原计数，新质量失败禁止作为完整成像输入，保存仍描述原始补零。

不猜包序号零点；无法确认采样原点单独标未知。按既有锚点解码不能称原点已验证。此处是健壮性修复，不是现场丢包根因结论。

- 按展开号排序，重排上限32个触发位置；高水位越过窗口封闭早期缺口，轮次关闭封闭剩余区间。迟到记录lateAfterSeal，不重复积分。
- 块覆盖50个位置，输入0、2、3保留1为缺口；异常大跨度用区间表示，不分配巨大数组。
- 第一版仍要求全部启用通道齐备，某卡不完整则整触发不可重建；不新增部分通道补偿算法。
- 无效位置不参与预处理/GPU积分；全无效块只推进位置与质量。保留raw布局所需占位但不可当有效零信号。
- 尾块1..49在轮次关闭/停止时提交，不跨轮凑块，不计UDP丢失。
- 保留现有角度公式和通道映射，公式g改为位置；Confirmed模式有效首触发为0，RelativeOnly模式声明相对基准。
- 服务按显式波长分流，不再用块内j%2。WL2移位前保存原始末列及身份，只有预期相邻关系成立才使用历史；跨缺口/换轮/配置/服务代清理历史。历史不足的对齐输出标无效，不拿更早数据替代。
- 可抽取小型共用WL2状态函数消除重复错误，不重写DAS和预处理算法。

### 4.6 保存顺序、短写与旁车

保留PAimage保存worker作为文件唯一所有者，不再启动第二个FileSaver线程。保留A/B转换、DAT布局和目录解析规则。

1. Start/Stop/Rotate/Flush有明确命令序。Stop先封闭新保存准入并确定已接受尾边界，worker排空该边界后flush/close确认，不清已接受队列。接收不等待；UI异步显示Saving/Draining/Stopped/Error。
2. 连续命令不可相互覆盖未执行动作。控制命令用独立有界控制队列，容量64；重复Flush可合并，其余满时明确拒绝UI请求，不能静默丢命令或反压接收。帧带保存代及接受序号，命令按边界执行。
3. 保存队列满拒绝新帧并记录身份，已有帧继续写；会话标不完整，不丢最旧伪装完整。
4. 短写循环写剩余字节，返回0/-1进入Error，禁止无限重试；保留A/B实际偏移和失败范围，不重开同名文件截断已写内容。
5. A/B对应数据均写完才计Written；索引commit写完才计可核对保存完成。flush失败独立报告，不承诺断电持久化。
6. 每对A/B文件新增同基名.index.jsonl及会话manifest；UTF-8、schemaVersion=1。记录session、wire/expanded trigger、卡、样点、A/B偏移/长度、质量/补零、批次ID；64位ID用十进制字符串。
7. 行记录描述数据，批次commit确认DAT及索引成功。未commit尾部标未确认。轮次稍后归属用round_assignment区间事件，不重写整索引。

### 4.7 诊断留存与统计

常驻计数每秒快照；详细loop使用现有固定记录和非阻塞入口，后台分段滚动。原始trace保持现有默认语义，新增字段版本化，旧实机证据仍可分析。

- 分段按1秒或8MiB先到轮换；滚动保留可用的前5秒。BurstMark、首次缺口/严重故障申请冻结前后各5秒，重叠合并；冻结段不可滚动删除。
- 总留存默认256MiB、最多8个独立冻结窗口。预算不足拒绝新冻结并标coverageIncomplete，不覆盖既有证据。预算可能不足5秒时必须标缺覆盖，不谎报足窗。
- 清理只限本run内未冻结且未被导出引用的旧段，先验证绝对路径。导出固定片段引用，防止边导出边删除。
- 分开retentionEvicted、queueDropped、freezeRejected、budgetExhausted、ioWriteFailed、exportTruncated。下一条记录放不下即置budgetExhausted，不能误记IO失败；summary统一读真实状态。
- 窗口按时间及序号声明覆盖；预期滚动淘汰不等于窗口丢记录。旧全量日志继续按旧守恒方式解释。
- 接收线程禁止JSON、文件I/O、系统命令、等待导出。
- UI分开“应用未见触发（观测范围内）”“触发内报文不完整”“质量未知”“保存失败”“成像丢弃”“显示跳帧”。不得写成采集卡未收到触发。
