> 2026-09-05 当前工作区已完成迁移，见根目录 `HANDOFF.md` 的“当前工作区状态覆盖说明”。不要为日常增量构建重复运行迁移脚本；它会保留并重新生成构建目录。
>
> 修复前快照为 `9342af1`。迁移脚本现在先检查工具链和输入库，支持 `-CheckOnly`；补充了模拟器和 UDP 回放工具的构建。验证允许 HEAD 在导入基线之后，并检查两个当前缓存路径与 CUDA DLL 哈希，已修正 PowerShell `$HOME` 保留变量冲突。
>

>
> 本包脚本与说明在迁移修复中有更新，`迁移包SHA256.txt` 同步为当前包内容；bundle 和 CUDA 预编译库未变。`HANDOFF.md` 包内副本与根目录同步。

本文件夹用于修复“把项目内容直接复制到新工作区”后必然出现的两个问题：

1. **不是 Git 仓库**：普通复制通常不包含隐藏目录 `.git`，所以无法核实提交号/分支/未提交修改。
2. **构建缓存引用旧绝对路径**：`build\` 下的 CMake 生成物（`CMakeCache.txt`、`build.ninja`/`Makefile`、
   `*.obj` 等）全部写死旧工作区路径，复制到新路径后不可直接使用。

## 新会话操作步骤

### 第 0 步：把整个 `_migration_pack` 文件夹放到新工作区根目录

要求最终布局：

```text
<新工作区>\
├── HANDOFF.md
├── MC_410T_MultiCard\
├── RadiusCalibration\
├── testdata\
├── _migration_pack\
│   ├── 迁移修复Git.ps1
│   ├── 迁移重建构建缓存.ps1
│   ├── 迁移后验证.ps1
│   ├── 迁移包SHA256.txt
│   └── realtime_imaging_migration.bundle
...
```

传输完成后可先用 `迁移包SHA256.txt` 校验关键文件完整性（尤其 231MB 的 bundle）。


### 第 1 步：恢复 Git 仓库（不覆盖工作区）

```powershell
cd <新工作区>
pwsh -ExecutionPolicy Bypass -File .\_migration_pack\迁移修复Git.ps1
```

预期：
- `HEAD = 8000b763c56a2da38ee7d50877a80126c57e1e5a`
- 分支出现 `master`、`backup/cf-dmas-pcf-20260816`、`backup/sysdelay-per-channel-20260817`
- `git status --short` 能看到交接文档第 3.2 节描述的未提交修改。

原理：脚本执行 `git init` → `git fetch <bundle> +refs/heads/*:refs/heads/*` →
`git reset master`（mixed reset）。reset 只更新 HEAD/索引，**不会覆盖工作区文件**，
所以复制过来的未提交改动全部保留。

### 第 2 步：重建路径相关的 CMake 缓存

```powershell
cd <新工作区>
pwsh -ExecutionPolicy Bypass -File .\_migration_pack\迁移重建构建缓存.ps1
```

- 工具链路径与旧机相同则直接运行；不同则指定：
  `-QtRoot "D:\你的Qt6.8.0路径"`，或 `-CmakeExe "C:\...\cmake.exe"`。
- 脚本只改 `MC_410T_MultiCard\delivery\build` 与 `PALiveImagingSimSender\build`；
  旧 build 目录改名 `*_oldpath_<时间戳>` 保留，不删除。
- CUDA 不重编：脚本把 `prebuilt_cuda\bin` 复制到 `delivery\third_party\ring_recon_cuda_prebuilt\bin`
  并作为 `RING_RECON_CUDA_IMPORT_LIB/BIN` 重新 configure MinGW。
- 如果新机器没有 Qt 6.8.0 / MinGW 13.1，需先安装并把路径传给脚本；脚本会明确报缺哪个工具。

### 第 3 步：一次性核对

```powershell
pwsh -ExecutionPolicy Bypass -File .\_migration_pack\迁移后验证.ps1
```

全部 PASS 才可认为迁移完成。

## 后续：CUDA 需要重编时

当前未提交代码**没有**改 `ring_recon_cuda.cu/.h`，所以迁移时直接用 prebuilt DLL 即可。
如果以后改了 CUDA 源码，按根目录 `HANDOFF.md` 第 7.2 节在**新机器**上执行
vcvars64 + nvcc(sm_89) + link，再用 gendef/dlltool 生成导入库；不要复制旧 build 目录里的
CUDA CMake 缓存来“改路径复用”。

## 常见失败排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `迁移修复Git.ps1` 报 bundle not found | `_migration_pack` 没有整包复制 | 重新复制整个文件夹，确认 bundle 存在 |
| `迁移修复Git.ps1` 报 No git found | 新机没有系统 git，且没复制 `_tools\git` | 复制原工作区 `_tools\git`，或加 `-GitExe "<git.exe 路径>"` |
| `git status` 显示大量 D/?? 而不是 rename | 未 `git add`，rename 未暂存 | 正常；新旧路径一起 `git add` 后再看 `git diff --cached --find-renames` |
| CMake configure 报 Qt6_DIR/compiler 缺失 | 新机 Qt/MinGW 路径不同 | 传 `-QtRoot` 或 `-CmakeExe` |
| 链接报 `undefined reference` | CUDA 导入库路径没配对 | 确认 `prebuilt_cuda\bin\libring_recon_cuda.dll.a` 已复制到 `delivery\third_party\ring_recon_cuda_prebuilt\bin` |
| `ld: Permission denied` | MC410T_Receiver.exe / ImagingSvc.exe 正在运行 | 脚本带 `-ForceStopApps` 或手动结束进程 |
| 运行程序缺 CUDA 运行时 | `cudart64_12.dll` 不在 exe 旁 | 把 `prebuilt_cuda\bin\cudart64_12.dll` 复制到 `build\mingw_make\bin` |
