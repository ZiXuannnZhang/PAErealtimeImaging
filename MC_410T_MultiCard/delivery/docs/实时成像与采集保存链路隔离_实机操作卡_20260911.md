# 实时成像与采集保存链路隔离：实机操作卡

## 每轮固定条件

1. 使用同一台笔记本、同一外接网卡、同一采集卡与 FPGA 配置。
2. 每轮设置 4000 次有效触发，并确认物理侧实际发出 4001 次；记录首触发过滤结果。
3. 分别设置 40 Hz、20 微秒采集时间和 50 微秒采集时间。
4. 每轮开始前导出/清空本轮应用诊断窗口，记下 runId、measurement session、保存目录、成像配置和服务状态。
5. 不修改采集卡、LabVIEW、触发 FPGA、保存格式和首触发过滤规则。

## 四组场景

对 20 微秒和 50 微秒分别执行：

1. 保存开、成像关。
2. 保存开、成像正常：成像服务先就绪，再开始采集。
3. 成像延迟启动：先开始采集与保存，稳定后再启动成像服务。
4. 成像服务停止：采集中主动停止 ImagingSvc，继续完成剩余触发。

## 每轮检查

- 入口：`recvfromDatagrams`、短包、重复包、包序号缺口。
- SourceCore：完整卡帧、不完整帧、启动过滤、同步过期、有效触发。
- 保存：`saveQueueEnqueued/Dequeued/CurrentDepth/PeakDepth/Full`，FileSaver 成功计数、失败和最终文件大小。
- 成像：`enqueueAttempts/enqueued/dequeued/currentDepth/peakDepth`，所有 drop 原因，块形成、提交、跳过、异常。
- 耗时：接收 drain/loop gap、save worker max、imaging submit/worker max、ImagingSvc 处理时间。
- 停止顺序：接收停止后保存队列降到 0、文件关闭；成像剩余项按 Stopping/ServiceNotReady 丢弃。

## 通过判据

- 每轮保存有效触发计数不随成像开启、延迟、队列满或服务停止而变化。
- 成像 `Accepted` 只对应实际入队；所有未入队数据都有明确原因。
- 成像队列满期间接收和保存仍前进，保存队列无由成像引起的深度跃升。
- 入口缺包、SourceCore 不完整、保存队列丢弃、成像旁路丢弃可分别核对，不能互相代替。
- 末尾不足一个成像块只记成像进度，不报 UDP 丢包。

## 留存材料

保存每轮诊断 ZIP、应用日志、保存文件清单及大小、ImagingSvc 日志、物理触发确认记录和场景/参数表。报告中分别标记代码验证、软件压力、实机验证和未知项。
