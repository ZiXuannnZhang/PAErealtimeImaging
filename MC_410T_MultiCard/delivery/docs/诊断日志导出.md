# 诊断日志导出

本功能用于把采集服务器上的运行证据带回其他电脑分析，重点还原多余目标 IP 的入选、就绪判定、配置发送和反馈过程。

## 使用方式

在主窗口“运行日志”区域点击“导出诊断日志…”，选择本次或历史运行，填写可选现场说明并选择 ZIP 保存位置。将完整 ZIP 复制到分析电脑，无需安装额外压缩工具或采集数据转换工具。

故障发生后尽量及时导出。程序停止监听后仍可导出；重启后可以选择之前保存的运行。导出不重新扫描网络，不发送采集卡控制命令。

## 判读原则

- 卡号表示目标 IP 列表中的位置，不是通道号。目标列表可能包含并非采集卡的可达设备。
- “ARP 就绪”表示地址可达；“收到 18 字节包”是另一条独立证据。二者均不能替代配置确认。
- `sendto` 成功表示本机发送接口返回成功，不证明远端已收到。
- 当前配置反馈按源 IP、报文长度及配置状态判定。日志配置编号仅用于本地关联，协议没有事务编号，迟到反馈的真实归属不能据编号断言。
- 网络快照反映记录时的本机信息；路由推导结果不是抓包证据，缺失 MAC 也不等于设备不存在。
- 应同时查看摘要中的完整性说明。日志丢弃、轮转、写入故障或异常退出可能导致证据不全。

## 导出文件

| 文件 | 用途 |
| --- | --- |
| `summary.txt` | 中文运行摘要及逐卡诊断结果 |
| `runtime.log` | 界面日志、Qt 和启动日志 |
| `events.jsonl` | 带序号、时间和会话标识的结构化事件 |
| `network.json` | 按时间保存的本机网络快照 |
| `settings.json` | 当次实际参数及诊断状态快照 |
| `manifest.json` | 格式、导出边界、校验值和完整性信息 |

## 维护边界

日志功能不改变扫描入选规则、配置报文、反馈接受条件、重试规则及成像算法。自动虚拟发现继续保持删除状态。既有同机联调工具可用于回归，但通过本机测试不表示真实服务器和四张物理卡已验收。

## 验证记录

2026-09-06：正式 `build/mingw_make` 的 `MC410T_Receiver` 构建通过。独立 CTest 覆盖日志 ZIP/导出截点、并发写入、写盘失败内存兜底、历史与异常退出恢复、导出界面、Windows 只读网络快照。

实际控制器回环测试覆盖四目标全部确认、第五目标仅 ARP 就绪后配置超时（首次发送加三次重试）、18 字节反馈触发重发与计数重置、重复及迟到反馈，并检查配置证据落盘。58 字节配置报文通过固定预期值校验。四卡各 80 次触发、40 Hz 的 UDP 回放在不导出和后台导出两种情况下均完整接收，丢包与不完整触发均为零。

测试源码位于 `delivery/tests`，构建目录为 `build/mingw_make/diagnostic_tests`。先用同一套 Qt/MinGW 配置和构建，再使用 `windeployqt` 部署测试运行依赖（界面测试另需 `platforms/qoffscreen.dll`），执行 `ctest --test-dir build/mingw_make/diagnostic_tests --output-on-failure`。构建日志为 `build/mingw_make/diagnostic_export_build.log`。
